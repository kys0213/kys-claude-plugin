# 사용자 승인과 위임 기본값을 좁히고 작문 하드 규칙을 완화한다

> **Plan — 이 시점의 결정 기록.** 현재 정책의 신뢰 소스가 아니다.
> 날짜: 2026-11-12 · 브랜치: claude/clever-johnson-dbk5wi · 이슈: 없음 · 승인 출처: 사용자 승인

## 배경

Anthropic 의 Fable 5.2 프롬프트 가이드(`platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2`)는 이전 모델용으로 쓴 지시문 중 비용만 늘리거나 부작용을 내는 유형을 꼽아요. atelier 에서 걸리는 것은 셋이에요.

- **쌓인 주의 문구와 불필요한 승인 요청** — 가이드는 Fable 5.2 가 지시를 엄격하게 따라서, 승인 규칙이 넓으면 일상 작업까지 멈춘다고 해요. 승인이 필요한 단계를 목록으로 적고, 절대 규칙은 범위와 이유를 붙여 다시 쓰라고 권해요. atelier 는 "설계 → 사용자 승인 → 구현"을 모든 변경의 기본값으로 둬요. 모호함이 없는 작은 변경도 재진술 후 확인을 기다려요.
- **상시 위임 지시** — 가이드가 Fable 5.2 로 옮길 때 가장 먼저 다시 보라는 항목이에요. 위임을 권하는 프롬프트에서는 Fable 5.2 가 쉽게 위임하고, 서브에이전트가 세션 비용의 큰 몫을 차지해요. 템플릿은 "모든 단계의 실작업은 orchestrator 로 위임한다(조사·리서치도)"라고 말해요.
- **작문 하드 규칙** — Fable 5.2 는 스타일 규칙을 엄격하게 따라서, 수치 상한이 글을 뚝뚝 끊기게 만들 수 있다고 해요. 가이드의 보고서 문구는 STE100 을 권하면서도 "이어지는 생각은 문단, 별개 항목만 목록"이라고 해요. communicate 는 "개조식 우선, 줄글 최소화"와 전면 수준의 어절 상한을 둬요.

## 요구사항 (사용자 결정)

1. 승인 완화 수준: **지정 지점만 승인**. 설계 먼저 하기는 유지해요.
2. 적용 범위: **atelier 템플릿·grill 과 이 저장소 루트 `CLAUDE.md` 둘 다**.
3. 포함 항목: 승인 완화(A), 상시 위임 지시 축소(B), 작문 하드 규칙 완화(C).

## 사이드이펙트 조사

- orchestrator 는 바꿀 필요가 없어요. 모드 기본값이 자율이고(HITL 은 사용자가 단계별 확인을 명시할 때만), 자율 런의 승인 이벤트는 협의체 pass 예요. 사용자 승인이 기본값인 곳은 템플릿과 grill 뿐이에요.
- grill 이 사용자 확인 없이 커밋한 plan 을 "grill 합의"로 표기하면 orchestrator 에서 자기 승인이 돼요. 그래서 승인 출처를 정직하게 적도록 plan 작성 규칙에 `없음` 값을 더해요. 그 plan 이 orchestrator 로 가면 자율 런 규칙대로 협의체가 승인 이벤트를 만들어요.
- 위임을 강제하는 hook·CLI 는 없어요. `atelier orchestrator spawn-check` 는 model 미지정만 막아요. 문서만 고치면 돼요.
- 템플릿이 바뀌면 설치한 사용자의 drift 가 `DRIFTED` 가 되고 `/atelier:update` 로 맞춰져요. 의도된 동작이에요. CLI 는 템플릿을 런타임에 읽어서(`cli/src/drift/core/types.rs`) 빌드 산출물에 영향이 없어요.
- orchestrator 문서는 `scripts/check-decision-graph.sh` 줄 수 상한을 따라요. description 과 첫 문단만 바꾸고 줄 수는 늘리지 않아요.
- 테스트·스크립트가 바뀌는 문구를 검사하지 않아요 (`grep` 으로 확인).
- 이 변경의 편집 대상 파일에는 정리할 규칙 위반이 없어요. 선행 정리는 0건이에요.

## 결정과 근거

### A. 사용자 승인을 지정 지점으로 좁힌다

승인 지점(사용자만 정할 수 있는 결정):

1. 해석이 둘 이상으로 갈리는 의도
2. 공개 계약이나 사용자에게 보이는 동작의 변경
3. 되돌리기 어렵거나 저장소 밖으로 나가는 행위
4. 요청 범위 밖으로 넓어지는 변경
5. 도메인 의미의 결정

그 밖의 작업은 설계를 plan·커밋·PR 에 남기고 진행해요. 모호함이 없는 작은 변경은 한 줄로 재진술만 하고 확인을 기다리지 않아요.

- **템플릿** §작업 흐름 · §설계 최우선: 흐름을 `요청 → 설계(규모에 비례) → 산출`로 바꾸고 승인 지점 목록을 둬요. 목록의 단일 출처는 템플릿이에요 (보이스카웃과 같은 배치 — 템플릿은 모든 세션에 로드돼요). "구현 중 설계 변경이 필요하면 멈추고 재논의한다"는 승인 지점에 걸릴 때로 좁혀요.
- **grill** `SKILL.md`: description 의 "You MUST"를 빼요. 최소 발현을 "재진술 후 진행"으로 바꿔요. 미결 게이트는 승인 지점에 걸리는 항목에만 재질문을 요구하고, 그 밖의 심문자 의문은 명시적 가정으로 기록해 닫을 수 있게 해요(소리 없이 닫는 것은 여전히 금지). HARD-GATE 는 "승인 지점에 걸린 결정에 기대는 구현"으로 범위와 이유를 붙여요. 핸드오프에 승인 출처 표기 규칙을 더해요.
- **grill** `references/design-generation.md`: 설계 생성은 의도가 정해지지 않은 요청에서만 열려서 승인 지점 1에 해당해요. 승인은 유지하고 HARD-GATE 에 이유만 붙여요. 재진술 문구의 "+ 확인"을 고쳐요.
- **plan 작성 규칙** (`rules/policies/plan-writing.md`): 승인 출처에 `없음 (승인 지점 없음)`을 더해요.
- **루트 `CLAUDE.md`** §설계 최우선 원칙: 같은 기준을 자기완결 문구로 써요. 이 저장소 규칙은 atelier 를 설치하지 않은 기여자도 읽어서 템플릿을 가리키지 않아요.
- **유지하는 승인**: `spec-write`(spec 은 제품 정책이라 승인 지점 2·5), `workflow`(규칙 파일은 사용자 소유), `communicate` 외부 전송(지점 3), orchestrator 정지 조건 4.

### B. 상시 위임 지시를 규모 기준으로 좁힌다

- **템플릿** §작업 흐름 orchestrator bullet: "모든 실작업은 위임"을 "여러 단위로 벌어지는 일은 위임"으로 바꿔요. 위임 비용(맥락을 다시 실어야 하고, 결과는 요약으로만 돌아오고, 세션 토큰의 큰 몫)을 적어요. 몇 번의 도구 호출로 닫히는 단일 단위 작업은 메인이 직접 해요.
- **orchestrator** `SKILL.md`: description 에서 "Edit/Write 를 쓰려는 순간마다 위임"과 "read-only 조사도 위임" 트리거를 빼요. 첫 문단의 직접 수행 예외를 "한 턴 단일 파일 단순 편집"에서 "몇 번의 도구 호출로 닫히는 단일 단위 작업"으로 넓혀요. 불변식 1(런 안에서 메인은 tracked 파일을 직접 편집하지 않음)은 그대로예요.
- **communicate** · **spec-write**: "실제 Write 는 orchestrator 가 위임하는 sub-agent 가 한다"를 "규모에 따라 메인이 직접 하거나 orchestrator 로 위임한다"로 바꿔요.

### C. 작문 하드 규칙을 완화한다

- "개조식 우선, 줄글 최소화" → "서로 별개인 항목은 목록, 이어지는 생각은 짧은 문단". 대상: communicate `SKILL.md` 기준선 표, `references/writing-standards.md` STE100 밖의 규칙, `output-styles/communicate.md`, 템플릿 §사람에게 전달하는 글. 기준선 항목 이름을 나열하는 참조 문서(`html-report.md`, `delivery-context.md`)와 description 의 "개조식"도 맞춰요.
- 전면 수준의 수치: 절차 문장 15어절은 상한으로 유지하고, 설명 문장 20어절과 문단 6문장은 목표로 바꿔요. 절차는 짧을수록 따라 하기 쉽지만, 설명을 수치에 맞춰 쪼개면 생각의 연결이 끊겨요. STE100 자체는 유지해요.

## 버린 대안

| 대안 | 이유 |
|---|---|
| 사용자 승인 전부 제거 | 사용자가 지정 지점 방식을 골랐어요 |
| 설계 단계 자체를 생략 | 비용이 거의 없고 plan 이 나중에 검토할 기록이 돼요 |
| 가이드의 소유권 문장("its design is up to you") 추가 | 승인 지점과 충돌하고, 가이드 실험에서 요청하지 않은 변경과 동작 변경이 늘었어요. 우리 작업에서 측정한 적도 없어요 |
| 가이드의 "끝까지 마치기" 문구 추가 | 가이드는 일찍 멈추는 현상을 관측한 뒤에만 넣으라고 해요. 아직 관측되지 않았어요 |
| 승인 지점 목록을 grill 에 두고 템플릿이 가리키기 | grill 은 트리거될 때만 로드돼요. 모든 세션에 로드되는 템플릿이 출처여야 해요 |
| orchestrator 승인 마커 규칙도 완화 | 자율 기본값과 협의체 pass 로 이미 사용자 승인에 기대지 않아요. 자기 승인 방지 장치는 유지할 가치가 있어요 |
| 수치 상한을 모두 목표로 | 절차 문장은 짧아야 따라 하기 쉬워요 |
