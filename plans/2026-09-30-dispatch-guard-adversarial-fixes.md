> 날짜: 2026-09-30 · 브랜치: claude/ecstatic-hawking-e8ov7q · PR: #903 · 승인 출처: 사용자 승인

## 요구사항

2026-09-29 적대적 리뷰(판정 규칙·hook 런타임·계약/CI·의도 대비 실효 4관점)의 "결정적으로 고칠 수 있는 것" 묶음을 이 PR 에 반영한다.

1. 판정 규칙이 실제 실행 모델(`resolved_model`)을 쓴다.
   - 상속 경고: model 미지정이고, `resolved_model` 이 없거나 `parent_model` 과 같을 때만 낸다. 에이전트 정의가 다른 모델을 고른 경우(내장 Explore 등)는 침묵한다.
   - 상한 초과 경고: 요청 model 이 있으면 그것, 없으면 `resolved_model` 로 상한을 검사한다. Fable 메인이 model 없이 띄워 Fable 로 상속된 경우가 잡힌다.
2. 경고 문구를 자족적으로 바꾼다 — 이미 실행된 호출이라 재실행 불필요, 다음 dispatch 부터 적용, 상한 값을 문구에 직접, 자문 소집이면 무시 가능. 스킬 내부 번호("불변식 21", "표 1") 와 검사하지 않는 약속("시작 tier")을 뺀다.
3. hooks 모듈: `next(e)` 가 던져도 spawn 사실을 지운다, 실패한 Agent 결과(`isError`)에는 경고를 붙이지 않는다.
4. orchestrator SKILL.md 표 1 의 집행 위임 상한과 CLI 사다리가 어긋나면 실패하는 테스트를 둔다. 표만 바뀐 PR 에서도 돌도록 CI 트리거를 넓힌다.
5. 존재하지 않는 파일을 extends 하는 `plugins/atelier/tsconfig.json` 을 지우고, 타입 생성 절차를 README 에 적는다.
6. README: 자문 소집에도 경고가 붙는다고 바로잡는다. 사후 경고라 첫 호출은 막지 않는다는 점, 한계 두 가지(tier 를 판별할 수 없는 모델 id 에서 상한 검사가 꺼진다, 구버전 CLI 에서는 무동작)를 적는다.

## 정책 결정 (사용자 승인)

- 상속 경고는 차단으로 올리지 않는다 — 모든 세션의 Agent 호출에 적용되고, 정의가 우연히 부모와 같은 모델을 고른 경우의 오탐이 남는다. 필요해지면 plugin 옵션으로 켜는 선택 기능으로.
- 자문 소집의 상한 초과 경고는 감수한다 — 자문 여부는 프롬프트 의미라 결정적으로 알 수 없다. 문구로 무시 가능함을 안내한다.
- compaction 지시는 모든 메인 compaction 에 조건부로 둔다.
- tier 를 판별할 수 없는 모델 id, 구버전 CLI 는 한계로 문서화만 한다.

## 검토한 대안

| 대안 | 판단 |
|---|---|
| 상속 경고를 요청 model 부재만으로 판정(현행) | 버림 — Explore 등 정의가 모델을 고른 타입에 오경고. 실세션 확인 |
| 상한 검사를 요청 model 로만(현행) | 버림 — 상속이 가장 흔한 상한 위반 경로인데 놓친다 |
| 판별 불가 id 에 "판단 불가" 경고 | 버림 — 그런 환경 사용자에게 매 호출 노이즈 |
| 표 동기화를 주석으로만 | 버림 — 표가 이미 바뀌는 중인데 기계적 검사가 없다 |
