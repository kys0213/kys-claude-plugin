# 12 — communicate: 보고서를 HTML 레포트로

> **Plan — 이 시점(2026-10-20)의 결정 기록.** 현재 정책의 신뢰 소스가 아니다. "지금 어떻게 동작해야 하는가"는 `plugins/atelier/skills/communicate/` 의 문서와 `plugins/atelier/scripts/report/` 코드가 갖는다.
> **계기**: "communicate 스킬에 ASD-STE100 기반 HTML 레포트를 기본 적용하면 좋겠다. Karpathy 의 제안을 참고해 개선해 보자."

## 1. 배경

- Andrej Karpathy 가 2026-10-02 X 게시물에서 LLM 출력을 이해하기 쉽게 만드는 형식 사다리를 제안했다: ASD-STE100 문장(엄격히 말고 "80% 수준") → 다이어그램 → 인터랙티브 HTML → 설명 영상. 원문은 직접 확인하지 못했고, 여러 2차 출처의 요약이 서로 일치했다.
- 2차 출처들이 공통으로 짚은 한계: 사다리를 오를수록 읽기는 쉬워지고 검증은 어려워진다 ("결과물은 보여 주는 화면이지 근거가 아니다").
- communicate 스킬은 1단(STE100 80%)을 이미 기준선으로 갖고 있었다. 2·3단은 없었고, 출력은 텍스트·마크다운만 전제했다.

## 4. 사이드이펙트 조사

- `output-styles/communicate.md` 는 매 턴 채팅에 강제 적용된다 → 채팅은 텍스트 유지라고 경계 절에 한 줄 추가.
- `delivery-context.md §6 서식 표현력` 은 "제한적/풍부" 두 칸뿐이었다 → "브라우저" 칸 추가.
- `templates/claude-md/CLAUDE.md` 의 Communication 절은 사용자 프로젝트로 drift sync 되는 최소 요약이다 → 손대지 않는다. 바꾸면 모든 설치 프로젝트에 drift 가 생기고, 스킬이 우선한다고 이미 명시돼 있다.
- `tools/validate` 는 SKILL.md 의 `${CLAUDE_PLUGIN_ROOT}` 경로가 실제로 있는지 검사한다 → 템플릿·스크립트 경로를 실제 파일로 둔다.
- 이 실행 환경에서 `cdn.jsdelivr.net` 이 프록시 정책으로 막혀 있었다. 사내망 독자도 같은 처지일 수 있다 → FR-4 를 CDN 로딩만으로는 만족할 수 없다.

## 5. 설계

### 5.1 렌더링 보장: 작성 시점에 SVG 로 굽는다

`scripts/report/render-report.mjs` 가 헤드리스 Chromium 으로 레포트를 열어 Mermaid 를 렌더링하고, 결과 SVG 를 파일에 구워 넣은 뒤 로더를 지운다. 네트워크를 막고 다시 열어 외부 요청·스크립트 오류·빈 다이어그램이 없는지 확인한 뒤에만 원래 파일을 바꾼다.

- 종료 코드: 0 OK / 1 BROKEN(고칠 것 있음) / 2 UNVERIFIED(검증 수단 없음).
- CDN 이 막힌 작성 환경은 `--mermaid-dist` 로 npm 에서 받은 로컬 mermaid 를 쓴다.
- 결정적 변환(자리표시자 검사·SVG 치환·로더 제거)은 `bake.mjs` 순수 함수로 분리해 `node --test` 로 고정한다. 브라우저 구동부는 테스트하지 않고 수동 시나리오로 확인했다 (정상·문법 오류·다이어그램 없음·빈 템플릿·CDN 차단·재실행).

### 5.2 자리표시자는 `data-fill` 속성

처음엔 `{{...}}` 를 썼다. GitHub Actions 의 `${{ secrets.X }}` 같은 정상 본문과 겹쳐 오탐이 나서 속성 표식으로 바꿨다.

### 5.3 버린 선택지

| 선택지 | 버린 이유 |
|---|---|
| 모든 대화 밖 산출물을 HTML 로 | 슬랙·PR 은 HTML 을 렌더링하지 못한다. 매번 파일이 생긴다 |
| 인라인 SVG 를 손으로 그리기만 허용 | 사용자가 Mermaid 를 원했다. 작성 비용도 크다 |
| Mermaid 를 CDN 에서 그때그때 불러오기만 | 네트워크가 막힌 독자에게는 그림이 안 보인다 (이 환경에서 실제로 막혔다) |
| 렌더링을 `atelier` Rust CLI 서브커맨드로 | 브라우저 구동이 필요해 Node + Playwright 가 맞다. 바이너리에 브라우저 의존을 넣지 않는다 |
| 사다리 4단(영상)까지 | 만들고 검증할 도구가 없다 |
