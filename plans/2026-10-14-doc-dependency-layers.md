# 문서 의존성을 단방향으로 정리한다

> **Plan — 이 시점의 결정 기록.** 현재 정책의 신뢰 소스가 아니다.
> 날짜: 2026-10-14 · 브랜치: claude/confident-davinci-7uqabp · 이슈: 없음 · 승인 출처: 사용자 승인

## 배경

spec 한 줄을 바꾸면 영향받는 코드만 고치면 돼야 해요. 그런데 지금은 주석·plan·스킬·룰이 서로를 경로와 절 이름으로 가리켜서, 한 곳을 바꾸면 가리키는 곳을 찾아다니며 함께 고쳐야 했어요. 사용자는 각 문서의 책임을 분명히 하고 의존을 한 방향으로만 두기를 원해요.

## 결정

1. **층과 방향** (사용자가 정의)
   - core: CLAUDE.md · AGENTS.md · rules · skills · agents · commands · output-styles. 서로 가리키지 않는다. 같은 종류끼리도 마찬가지다.
   - spec → core, plan → spec·core 만 허용한다.
   - code(주석 포함)와 문서는 어느 방향으로도 서로 가리키지 않는다. spec 의 `related_paths` 규약도 없앤다.
   - 주석은 코드·spec·plan 으로 알 수 없는, 코드에서만 판단 가능한 것만 남긴다.
2. **허용 범위** (사용자 결정)
   - 스킬·에이전트·커맨드는 이름으로 부를 수 있다. 파일 경로·절 이름은 안 된다.
   - rule 은 이름으로도 부르지 않는다. 경로에 따라 자동 로드되기 때문이다.
3. **판별 질문**: "가리킨 대상이 바뀌면 이 문장도 고쳐야 하는가?" 문서 종류나 저장 위치("plan 은 `plans/` 에 남긴다")를 말하는 것은 특정 문서가 바뀌어도 고칠 일이 없으므로 의존이 아니다. 커맨드가 설치·복사하는 파일 경로도 그 커맨드 자신의 작업 대상이라 의존이 아니다.
4. **배치**: 별도 정책 룰 `doc-dependency.md` 로 두고, 정책 룰 매니페스트에 등록해 setup·drift 가 함께 다루게 한다. 템플릿 CLAUDE.md 에 넣으면 모든 세션에 상시 로드되므로 버렸다 (사용자 선택).
5. **기존 위반은 이번에 전부 정리한다** (사용자 결정). 대상은 atelier 의 core 문서·spec·CLI 주석과 출력 문자열, 그리고 레포의 orchestrator 문서 규약과 검사 스크립트다.
   - grill ↔ orchestrator 핸드오프는 경로 포인터 없이 각자 자기 몫만 적는다.
   - CLI 의 push-check 안내 문구는 git 스킬 절을 가리키는 대신 다음 행동을 직접 말한다.
   - orchestrator 문서 검사 중 "외부가 절 이름으로 가리킨다"를 전제로 한 검사(외부 계약 표면 실존)를 없애고, 그 규약 절을 "이름으로만 부른다"로 바꾼다.

## 버린 대안

| 대안 | 이유 |
|---|---|
| 템플릿 CLAUDE.md 에 그래프 추가 | 모든 세션에 상시 로드된다 |
| 정책 룰 3개(spec·plan·rules 작성법)에 나눠 적기 | 여러 문서에 걸친 관계라 사본이 생긴다 |
| 첫 초안: CLAUDE.md→rules, rules→spec, spec↔code 허용 | 사용자 모델과 달랐다. core 독립·문서↔코드 금지로 바꿨다 |
| spec·plan → code 허용 | 코드를 바꿀 때 문서를 따라 고치게 된다 (사용자 결정) |
