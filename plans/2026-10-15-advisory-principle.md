# 자문 소집을 규칙 대신 원칙으로 유도한다

> **Plan — 이 시점의 결정 기록.** 현재 정책의 신뢰 소스가 아니다.
> 날짜: 2026-10-15 · 브랜치: claude/peaceful-darwin-plcyfs · 이슈: 없음 · 승인 출처: 사용자 승인

## 배경

orchestrator 의 자문(advisor) 소집이 기대대로 일어나지 않아요. 사용자가 직접 "자문을 받아라"라고 말해야 불려요.

원인은 규칙이 부족해서가 아니라, 문서가 자문을 "비싸고 위험한 예외"로 가르쳐서예요.

- 표 1 의 자문 tier 를 "집행 위임 tier 상한의 **유일한 예외**"로 적었어요.
- `트리거 시` 활용을 "**에스컬레이션 직전**과 협의체 tie-break 에서만"으로 적었어요. 자문이 막혔을 때 쓰는 마지막 수단으로 읽혀요.
- 비가용·생략 시 행동이 "원래 하려던 에스컬레이션으로"예요. 자문이 에스컬레이션 경로의 한 단계라는 전제가 깔려 있어요.
- `적극` 활용의 선제 소집 목록은 표 1 아래 각주 문단에만 있어요. 모델은 이 문단을 tier 를 고를 때만 읽어요.

또 orchestrator 문서 규약이 형식을 불변식·정지 조건·기본값 표·환경 계약·절차로 제한해서 방향·가치를 둘 자리가 없었어요. 사고가 날 때마다 불변식 한 행을 더하는 구조라 규칙이 계속 늘어요.

## 결정

1. **원칙 형식을 도입한다** (사용자 방향). 원칙은 판단이 무엇을 중시할지를 이유와 함께 적는 짧은 산문이에요. SKILL.md 의 `원칙` 절 한 곳에만 둬요. 조건→행동 목록이 되면 판단 대본이므로 이유로 되돌려요.
2. **이번 범위는 자문만** (사용자 선택). 원칙은 자문 하나로 시작해 효과를 본 뒤 orchestrator 전반으로 넓혀요.
3. **반대 방향을 가르친 문장을 정리한다.**
   - 표 1 의 `자문 활용` 열과 각주 문단을 지워요. 언제 소집할지는 원칙에 비추어 메인이 판단해요.
   - "유일한 예외" → 자문은 집행이 아니라서 집행 상한과 무관하다고 적어요.
   - 비가용·생략 시 행동 → "자문 없이 메인이 판단을 이어 간다"로 바꿔요.
   - `max_advisory_consults` 를 활용 수준과 무관하게 가용이면 5 로 통일해요. 상한은 폭주 방지용이지 사용량 목표가 아니에요.
4. **사고 대응 질문을 바꾼다.** 규약 §10 을 "어떤 원칙이 없었나, 어떤 문장이 반대 방향을 가르쳤나"부터 묻도록 고쳐요. 불변식은 조용히 오염되거나 되돌리기 어려운 결과를 막을 때만 써요.

## 버린 대안

| 대안 | 이유 |
|---|---|
| 자문 트리거 이벤트 표 + 절차 단계마다 확인 문장 | 규칙이 또 늘어요. 사용자는 규칙보다 방향으로 유도하기를 원했어요 |
| 자문 생략 시 근거 기록을 불변식으로 강제 | 같은 이유. 품질 판단을 불변식으로 묶는 형태예요 |
| Claude Code hook 으로 자문 리마인더 주입 | 룰베이스 로직이 들어가요 (사용자 거절) |
| `자문 활용` 열 유지 | Fable·Sonnet 메인에서 "트리거 시에만"이 다시 마지막 수단 프레이밍을 가르쳐요. 자문자가 메인보다 강할수록 가치가 크다는 점은 원칙 문장이 대신 말해요 |

## 영향

- Fable·Sonnet 이하 메인도 선제 소집을 할 수 있게 되고, 자문 예산이 2 → 5 로 늘어요.
- 원칙은 행동을 확률적으로 유도해요. 효과는 실제 런에서 자문이 불리는지로 확인해요.

## 범위 밖

- orchestrator 전반의 불변식·정지 조건을 원칙 층과 불변식 층으로 다시 나누는 일은 후속으로 남겨요.
- orchestrator 가 뜨지 않는 일반 대화의 자문 진입점은 다루지 않아요.
