# 자율 런의 설계 승인을 협의체 pass 로 한정한다

> **Plan — 이 시점의 결정 기록.** 현재 정책의 신뢰 소스가 아니다.
> 날짜: 2026-10-01 · 브랜치: claude/beautiful-johnson-fdvrif · 이슈: #904 · 승인 출처: 사용자 승인 (2026-10-01 설계안 1·2·4 제시 후 "진행", 면제 처리는 "자율에선 면제 금지" 선택)

## 요구사항

1. 자율 런은 사용자 grill 대신 아키텍트 협의체가 설계를 검증해야 한다 (`templates/claude-md/CLAUDE.md` 의 자율주행 모드 문구). 그런데 orchestrator 에는 이 연결이 없어, 메인 혼자 쓴 plan·task 로 구현까지 간 런이 있었다 (#904: 자율 판정 8세션 중 협의체 소집 0).
2. 협의체를 건너뛴 통로 둘을 막는다.
   - 실행 형태만 정한 발화("오케스트레이터 모드로")가 사용자 승인으로 기록됐다.
   - "자명한 작업" 면제 판정이 도메인 의미 결정이 걸린 작업에 쓰였다.
3. HITL 런에 협의체를 강제하지 않는다 — 사용자와의 grill 합의가 같은 검증 역할을 한다.

## 현재 상태 (사이드이펙트 조사)

- 원인 조항: `skills/orchestrator/SKILL.md` 불변식 16 · 표준 절차 1, `references/procedures.md §자율 실행 루프` 3, `references/contracts.md §plan 기록` 의 면제 항목 · `§설계 승인 마커` 의 승인 이벤트 정의.
- 표 7 은 종료 조건이 판정 가능하면 자율을 기본값으로 둔다. 자율 판정 비율 상승의 직접 원인이지만 이슈가 의도된 동작으로 봤으므로 그대로 둔다.
- 협의체는 표 2 에서 필수 등급이라 agent team 이 없으면 폴백 없이 에스컬레이션된다. 자율 런에 협의체를 강제하면 team 이 꺼진 환경의 자율 런은 멈춘다. #905 가 SessionStart 에서 team 을 켜 주므로 대부분 흡수된다.
- `grill` 은 합의 시점에 plan 을 커밋한다 (`grill/SKILL.md §종료와 핸드오프`). 사용자와 grill 로 합의한 뒤 자율로 실행하는 흐름은 이미 검증된 설계라 협의체를 다시 요구하지 않는다.
- 줄 수 상한(`scripts/check-decision-graph.sh`): `contracts.md` 238/250. 새 절 없이 기존 절 안에서 고친다.
- `rules/policies/plan-writing.md` 의 승인 출처 열거(사용자 승인 · grill 합의 · council pass)는 바뀌지 않는다.

## 결정

1. **사용자 승인의 성립 조건 (모드 무관)**: 메인이 plan 내용을 사용자에게 제시한 뒤 그 설계에 대해 받은 승인 발화만 인정한다. 설계를 제시한 뒤라도 실행 형태만 정하는 발화("오케스트레이터 모드로" · "자율로" · "병렬로" · "알아서")는 승인이 아니다.
2. **자율 런의 승인 이벤트**: 진입 전에 grill 합의나 사용자 승인으로 커밋된 plan 이 있으면 그것을 쓰고, 없으면 협의체 pass 만 인정한다. 표준 절차 1·자율 루프 3 의 "메인이 직접 분해" 분기는 HITL 에만 남긴다.
3. **면제 판정**: 자율 런에서는 쓰지 않는다 (사용자 선택). HITL 에서도 API 응답 · 공개 계약 · 데이터 스키마 · 영속 데이터 의미 · 권한이 걸린 작업은 면제하지 않는다.
4. 위 셋의 정의는 `contracts.md §설계 승인 마커` 한 곳에 두고, 불변식 16 과 절차는 그 결과만 적는다.

## 버린 선택지

- **CLAUDE.md 템플릿의 "자율이면 grill 하지 않는다" 삭제**: 자율 판정 자체는 의도된 동작이다. 지우면 원인(협의체 단계 누락)은 남고 자율 모드의 목적만 사라진다.
- **모든 런에 협의체 강제**: HITL 의 grill 합의와 중복이다.
- **자율 런 승인 = 협의체 pass 만 (진입 전 합의 plan 도 불인정)**: 사용자와 이미 합의한 설계를 협의체가 다시 검증하는 중복 비용이다.
- **자율에서도 면제를 남기고 기준만 좁히기**: 비용은 적지만, "자명하다"는 판단을 메인이 혼자 내리는 통로가 남는다. 사용자가 금지를 골랐다.
- **CLI 로 승인 출처를 검증**: 출처의 진위는 결정적으로 판정할 수 없다. 실행 근거 검증 CLI 는 #892 범위로 둔다.
