# CLI 레이어 컨벤션 (사용자 인터페이스)

> CLI는 시스템의 가장 바깥 경계다. 내부 리팩토링에 테스트가 깨지지 않아야 한다.

## CLI 코드는 `commands/` 아래에 둬라

- 인자 정의(clap `Parser`·`Subcommand`·`Args`), 서브커맨드 분기, 결과 포매팅은 그 도메인의 `commands/` 모듈에 둔다.
- 도메인 `mod.rs` 와 바이너리 `main.rs` 는 모듈 선언과 진입점 재노출·호출만 둔다.
- 레이어는 디렉토리로 정한다. 크레이트 디렉토리 이름(`cli/`)으로 정하면 core 까지 CLI 레이어로 묶인다.

## 블랙박스 TDD 필수

- 테스트는 내부 구현이 아닌 외부 동작(입력 → 출력)을 기준으로 작성한다.
- 외부 의존성(DB, API, 파일시스템)은 mock을 주입하여 격리한다.
- core/service/infra 내부가 리팩토링되어도 CLI 테스트는 깨지지 않아야 한다.

## 의존성은 생성자 주입으로 해결하라

- 외부 의존성(Git, FS, API 클라이언트 등)을 함수 파라미터로 반복 전달하지 마라.
- Service struct를 만들고 생성자에서 trait object를 주입받아라.
- 테스트에서는 mock을 주입하여 격리한다.

## 비즈니스 로직을 CLI에 두지 마라

- CLI는 인자 파싱 → service 호출 → 결과 포매팅만 담당한다.
- 조건 분기, 상태 변환 등 로직이 CLI에 있으면 service로 이동한다.
