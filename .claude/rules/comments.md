# 주석 작성 규칙

테스트 코드에도 같게 적용한다. 테스트의 의도는 테스트 이름과 코드가 말하고, 로직이 바뀌면 코드만 고치면 되어야 한다.

## 1. 어떤 문서에도 없는 code-local 맥락만 남긴다

현재 계약의 출처는 코드와 spec, 결정의 근거는 `plans/`, 변경 이력은 git log·PR 이다. 주석에 복제하면 여러 곳을 함께 고쳐야 하고 어긋나는 순간 스테일이 된다. 애매하면 지운다.

- DO: 코드만 봐서는 모르는 함정, 외부 도구·라이브러리의 비직관적 동작과 그 회피. 외부 동작을 적을 때는 확인한 사실만 적는다.
  - 예: `// retry: 이 라이브러리는 연결이 살아있어도 idle 5분 후 첫 호출에서 EOF 를 던진다 — 그래서 1회 재시도한다`
  - 예: `// 이 필드가 비어있으면 "지정 안 함" — 그 이상은 판단하지 않는다` (함수가 실제로 무엇을 그렇게 취급하는지만 서술)
- DON'T: 도메인·정책·결정 근거의 복제 ("이 규칙이 필요한 이유는 정책 X 때문")
  - 예: `// 정책상 관리자만 삭제 가능해야 하므로 여기서 role 을 검사한다` → 정책 근거는 spec 이 말한다. `// role 검사: admin 만 통과` 정도로 그친다.
- DON'T: 문서 포인터 (plan 경로, spec 절, 스킬의 불변식·표 번호)
  - 예: `// SKILL.md 표 1 참조`, `// plans/2026-xx-xx-foo.md 결정 3 참고` → 지운다. 필요하면 코드 자체가 계약을 드러내게 한다.
- DON'T: 이슈·PR 번호, 버전, "이전엔 X 였다" 같은 이력 narration
  - 예: `// #1234 에서 이 분기를 추가함`, `// v2 부터는 이 값을 무시`
- DON'T: 시그니처·반환 타입·분기 구조가 이미 말하는 동작을 doc 주석으로 다시 적지 않는다. private 함수의 doc 주석은 이름과 시그니처로 부족할 때만 쓴다. 다른 언어 구현과의 대응 설명도 마찬가지다.
  - 예: `// i 를 1 증가시킨다` (바로 위 `i += 1`), `// Go 쪽 구현과 동일한 로직`
  - 예 (형태): 함수 바로 아래 `match`/`if-else` 분기 각각을 문장으로 나열한 doc — 분기가 하나 늘 때마다 doc 도 같이 고쳐야 어긋나지 않는 형태라면, 그 doc은 분기 구조의 재서술이다.
- DON'T: 흩어진 계약을 주석으로 설명한다. 먼저 그 로직을 한곳으로 모을 수 있는지 본다. 모을 수 있으면 모으고 주석은 쓰지 않는다.
- 예외: 사용자에게 보이는 출력 문자열은 주석이 아니다. `plans/`·changelog 는 이력이 목적이라 narration 허용.

### 판별 체크리스트

- 이 주석은 코드가 바뀌지 않았는데 다른 문서(spec·plan·skill)가 바뀌면 틀려지는가? → 그러면 복제다, 지운다.
- 이 주석에서 경로·절 번호·이슈 번호를 지우면 남는 내용이 없는가? → 포인터다, 지운다.
- 이 주석을 지우고 코드만 읽어도 같은 결론에 도달하는가? → 그러면 what 의 재서술이다, 지운다.
- 이 doc이 private 함수에 있고 이름과 시그니처만으로 동작을 알 수 있는가? → 그러면 지운다.
- 이 주석이 설명하는 계약이 여러 함수에 흩어져 있어서 필요해진 것인가? → 그러면 로직을 모을 수 있는지 먼저 본다.
- 이 주석이 없으면 다음 사람이 반드시 한 번은 겪을 함정(외부 동작·비직관적 실패)을 알려주는가? → 그러면 남긴다.

## 2. 서술은 언어의 문서 주석 관용을 따른다

| 언어 | 항목·모듈 서술 | 코드 사이 서술 |
|---|---|---|
| Rust | `///` 항목, `//!` 모듈 | `//` |
| Go | 식별자 이름으로 시작하는 `//` | `//` |
| TypeScript | `/** */` | `/** */` |
| Shell | 파일 상단 `#` 블록 | `#` |

- 예외: 도구 디렉티브(`#[allow]`, `//nolint`, `// eslint-disable`, `// @ts-expect-error`, `# shellcheck disable`), 작업 마커(`TODO:`, `FIXME:`), 단계 이름만 있는 테스트 마커(`given`/`when`/`then`, Arrange/Act/Assert)는 언어의 라인 주석을 쓴다.
- DON'T: 테스트 단계 마커에 서술을 붙인다. 서술은 테스트 이름으로 옮긴다.
  - 예: `// given: 사용자가 로그인하지 않은 상태` → `// given` 만 남기고, 그 맥락은 테스트 이름(`fn rejects_when_not_logged_in`)으로 옮긴다.

## 기존 코드
