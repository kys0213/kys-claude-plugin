# 세션 칸반

> 이 머신에서 atelier 가 켜진 Claude Code 세션 전체를 한 pane 의 칸반으로 보여줘요. 세션 하나가 카드 하나이고, 컬럼은 세션이 지금 무엇을 기다리는지예요. 카드를 열면 그 컬럼에 맞는 상세와 행동이 나와요 — 질문·권한 요청·결정 요청에 답하고, 쉬는 세션에 일을 맡기고, 일하는 세션을 멈춰요. 오케스트레이터는 같은 보드를 읽어 레포별로 작업자를 부려요.

## 역할

여러 세션을 동시에 돌릴 때 "어느 세션이 내 답을 기다리는지", "어느 세션이 아직 일하는지·무엇을 하는지(백그라운드로 돌리는 에이전트 포함)", "어느 세션이 모든 일을 멈추고 쉬고 있고 직전에 무엇을 했는지", "어느 세션이 죽었는지"를 한눈에 보게 하고, 그 세션으로 가지 않고 답하거나 일을 맡기거나 멈추게 해요.

## 정책

1. **대상** — atelier 모드가 로드된 세션만 보여요. 모드가 없는 세션·다른 머신의 세션은 대상이 아니에요. `claude --bg` 로 띄운 백그라운드 세션도 모드가 로드되면 대상이에요.
2. **열기** — `/kanban` 으로 pane 을 열고, 다시 입력하면 닫아요. `/kanban delegate …` 처럼 인자를 붙이면 pane 을 열고 닫지 않고 칸반 위임(`kanban-delegate.md`)의 명령으로 다뤄요. `atelier` CLI 가 없거나 실패하면 인자가 있든 없든 열고 닫지 않아요(실패 처리). 넓은 화면은 대화 옆, 좁은 화면은 프롬프트 위에 놓여요.
   - 프롬프트 위 띠에도 버튼이 있어요(터미널·데스크톱 앱). pane 이 닫혀 있으면 `세션 칸반 열기`, 열려 있으면 `세션 칸반 닫기` 이고, 누르면 `/kanban` 과 같이 열고 닫아요. pane 의 닫기 표시로 닫아도 버튼이 바로 `세션 칸반 열기` 로 바뀌어요.
   - 설문이 띠를 쓰는 동안은 버튼이 비켜요. 다른 플러그인이 띠에 그린 것이 있으면 그 위에 버튼 줄을 얹어요.
3. **컬럼** — 순서는 고정이에요: 입력 대기 → 작업 중 → 쉬는 중 → 응답 없음. 빈 컬럼도 보여요.
   - **입력 대기**: 사람의 답을 기다려요. 카드에 무엇을 기다리는지 표시해요.
     - `권한 요청: <도구>` — 권한 확인 창.
     - `질문` — AskUserQuestion 질문 창. 질문이 열려 있는 동안은 화면이 무엇을 그리든 입력 대기예요. 질문은 그 질문의 결과, 칸반의 답, 턴의 끝이나 새 턴의 시작으로 끝나요. 질문 창이 열린 동안 줄 세운 프롬프트나 다른 도구의 결과·권한 요청으로는 끝나지 않아요. spinner 가 다시 그려져도 질문은 끝나지 않아요.
     - `결정 요청` — 턴이 끝나면서 사람에게 결정을 물었어요(데스크톱의 턴 끝 결정 카드, `WrapUp` 의 질문). 다음 턴이 시작되면 사라져요.
       - 턴 끝 응답이 평문으로 사람에게 묻고 끝났을 때도 결정 요청이에요. 메인 턴이 끝날 때마다(중단한 턴·빈 응답·이미 결정 요청이 있는 턴은 빼고) 작은 모델(Haiku)이 그 응답이 사람의 답을 기다리는지만 판단해요. 기다리면 선택지 없는 결정 요청이 되고, 질문 자리에 응답의 끝 200자를 보여요. 판단은 턴이 끝나고 몇 초 뒤에 들어오고, 그 사이 다음 턴이 시작됐으면 버려요.
     - `입력 요청` — MCP 입력 요청.
   - **작업 중**: 프롬프트를 받았거나 도구를 실행하고 있어요. 권한 확인·질문에 답한 직후부터 작업 중이에요(칸반에서 답한 경우 포함). 턴이 끝났어도 그 세션이 띄운 백그라운드 일이 남아 있으면 작업 중이에요 — 메인 오케스트레이터가 에이전트 스웜을 돌리며 결과를 기다리는 경우예요.
     - 백그라운드 일로 치는 것: 서브에이전트, Workflow, 원격(클라우드) 세션, 그리고 지금 일하는(대기·실행·하위 작업 대기 중인) 팀원.
     - 치지 않는 것: 백그라운드 셸(dev 서버 등)·Monitor 같은 상주 작업, 메시지를 기다리며 노는 팀원.
     - 턴이 끝날 때 엔진이 알려 준 진행 중 작업 목록으로 판단하고, 팀원은 세션이 마지막으로 본 에이전트 상태로 판단해요. 백그라운드 일이 남은 동안의 유휴 알림은 쉬는 중으로 만들지 않아요.
     - 서브에이전트·팀원이 도구를 실행해도 컬럼은 바뀌지 않아요. 서브에이전트·팀원이 권한을 묻거나 질문하면 입력 대기가 되고, 그 요청이 끝나면 묻기 전 컬럼으로 돌아가요. 머문 시간도 묻기 전 그대로예요.
   - **쉬는 중**: 턴이 끝났고 백그라운드 일도 모두 멈춰 다음 프롬프트를 기다려요. 막 시작한 세션도 여기예요.
   - **응답 없음**: 세션 프로세스의 생존 신호가 2분 넘게 끊겼어요(비정상 종료·멈춤). 직전 컬럼과 상관없이 여기로 옮겨요.
4. **카드** — 세션마다 테두리 있는 상자 하나로 그리고, 포인터를 올리면 테두리가 진해져요. 컬럼 제목과 카드, 카드와 카드 사이는 한 줄씩 띄워요. 이름, 그 컬럼에 머문 시간, 부제목을 보여요. pane 을 연 세션 자신은 `▶` 로 표시해요. 진행 상황이 있으면 한 줄, 쉬는 중이면 `직전: <직전 응답 첫 줄>` 을 한 줄 더 보여요.
   - 컬럼을 나란히 놓으려면 컬럼마다 26칸이 있어야 해요. 그보다 좁으면 컬럼을 세로로 쌓아요.
   - 이름은 저장소 이름이에요 — 원격 저장소 주소의 이름, 없으면 메인 작업 트리 디렉토리 이름, 저장소가 아니면 작업 디렉토리 이름. worktree 에서 도는 세션도 저장소 이름으로 보여요.
   - 부제목은 세션 제목, 없으면 첫 프롬프트, 그것도 없으면 사람이 쓴 가장 최근 프롬프트를 한 줄로 접어 60자로 잘라요. 비었거나 이벤트인 제목·첫 프롬프트는 건너뛰어요.
   - 사람이 쓴 프롬프트는 대화 입력·원격 제어·SDK 호스트로 들어왔거나 칸반에서 보낸 것 중, 호스트가 태그로 감싸 보낸 이벤트(사이드 세션 이벤트·작업 알림)가 아닌 것이에요. 백그라운드 작업 알림·예약 실행·세션 이벤트 같은 자동 프롬프트는 작업 중으로 바꾸기만 하고 "요청" 으로 보이지 않아요.
   - 엔진이 프롬프트에 붙인 `<system-reminder>` 안내문, 칸반 요청 머리말(13), 터미널 제어 문자는 보이지 않아요.
5. **진행 상황** — 응답 없음이 아닌 카드에 `할 일 <완료>/<전체> · <진행 중인 할 일>` 을, 작업 중 카드에는 이어서 `▸ <도구>: <대상>` 을 보여요. 턴이 끝나고 백그라운드 일로 작업 중인 카드에는 도구 대신 `▸ 백그라운드: 에이전트 <n> · 팀원 <n> · 워크플로 <n> · 원격 세션 <n>` 을 보여요(0개인 항목은 빼고, 모두 셀 수 없으면 `▸ 백그라운드 작업`).
   - 할 일은 세션의 Task 목록(`TaskCreate`·`TaskUpdate`)이 있으면 그것을, 없으면 `TodoWrite` 목록을 세요. 지운 할 일은 세지 않아요. 할 일이 없으면 이 부분을 빼요.
   - 진행 중인 할 일은 첫 번째 진행 중 항목의 진행형 문구(없으면 제목)이고, 40자로 잘라요.
   - 도구 대상은 도구 입력의 설명·파일·패턴·주소·명령 순으로 처음 있는 값이에요. 파일 경로는 파일 이름만, 40자로 잘라요. 턴이 끝나면 지워요.
6. **머문 시간** — 지금 컬럼에 들어온 시각부터 세요. 같은 상태가 이어지는 동안(도구를 여러 번 실행하는 동안, 백그라운드 일이 이어지며 턴이 끝나고 다시 시작하는 동안 등)은 다시 세지 않아요. 질문은 질문이 열린 시각부터, 결정 요청은 턴이 끝난 시각부터 세요. 응답 없음은 마지막 생존 신호부터 세요.
7. **정렬** — 입력 대기·작업 중은 오래 기다린 세션이 위, 쉬는 중·응답 없음은 최근 세션이 위예요.
8. **사라짐** — 세션이 정상 종료하면(`/exit`, `/clear`·`/resume` 으로 떠난 세션 포함) 카드가 바로 사라져요. 생존 신호가 24시간 넘게 없으면 그때 사라지고, 그 전에도 응답 없음 카드의 상세에서 지울 수 있어요(10). 그 세션에 남은 칸반 답·요청과 세션 기록도 같이 지워요.
   - 끝난 세션을 다시 열면(`--resume`·`/resume`) 카드가 다시 나타나요. 막 시작한 세션처럼 쉬는 중에서 시작하고 머문 시간도 다시 세요. 지난 실행이 기다리던 것(질문·권한 요청·결정 요청)과 도구 기록은 이어지지 않고, 제목·요청·직전 응답·할 일은 이어져요.
9. **갱신** — pane 이 열려 있는 동안 2초마다 다시 그려요. 닫혀 있으면 보드를 읽지 않아요.
10. **카드 상세** — 카드 제목을 누르면 pane 이 그 카드의 상세 화면으로 바뀌어요. pane 너비와 상관없이 상세가 보드 자리를 대신하고, 화면 맨 위부터 보여요. 맨 위의 `← 보드` 를 누르면 보드로 돌아가요. 한 번에 한 카드만 열어요. 갱신(9)으로 그 카드가 보드에서 사라지면 보드로 돌아가요. 상세의 "요청" 은 사람이 쓴 가장 최근 프롬프트예요(4).
    - 모든 컬럼의 상세는 맨 위에 **작업** 을 보여요 — 세션 제목(없으면 첫 프롬프트, 이벤트는 건너뛰어요)과 `위치: <작업 디렉토리>`. 제목이 아래 요청·이전 요청에 이미 보이면 빼요.
    - **이전 요청** 은 요청 앞에 사람이 쓴 프롬프트들이에요(4). 세션 기록이 남긴 최근 프롬프트 안에서 오래된 것부터 `<요청> · <경과>` 로 한 줄씩, 120자까지 보여요. 요청 바로 앞에 놓여요.

    | 컬럼 | 상세 | 행동 |
    |---|---|---|
    | 입력 대기 · 권한 요청 | 작업, 기다리는 것(`<도구>: <명령·파일·주소…>`), 이전 요청, 요청, 기다리기 직전 응답 | 허용 · 거부(12), 중지 |
    | 입력 대기 · 질문 | 작업, 이전 요청, 요청, 기다리기 직전 응답 | 질문 답하기(11), 중지 |
    | 입력 대기 · 결정 요청 | 작업, 이전 요청, 요청, 요약, 질문, 답 버튼 | 답 버튼 누르기, 직접 입력해 보내기 — 그 결정에만 들어가요(13) |
    | 작업 중 | 작업, 이전 요청, 요청, 할 일 목록(✓ 완료 · ▸ 진행 · · 대기), 최근 도구 5개와 각 경과 시간 | 중지(턴이 돌 때만) |
    | 쉬는 중 | 작업, 이전 요청, 직전 요청, 직전 응답, 할 일 목록 | 입력해 보내기 |
    | 응답 없음 | 작업, 이전 요청, 마지막 요청, 마지막 응답, 할 일 목록 | 보드에서 지우기 |

    - 요청은 300자, 응답은 앞 6줄(줄마다 200자), 기다리는 것은 120자까지 보여요. 할 일이 8개를 넘으면 완료한 것을 `✓ 완료 <n>개` 한 줄로 접고, 남은 것을 8개까지 보여요.
    - 기다리기 직전 응답은 질문·권한 요청이 시작될 때 그 세션의 마지막 응답이에요.
    - 보내기는 빈 글을 받지 않아요. 보낸 뒤에는 "보냈어요" 를, 받은 세션이 처리한 뒤에는 `보낸 요청: <결과> · <경과>` 를 보여요.
    - 중지는 한 번 더 눌러야 보내요(`정말 중지` / `취소`). 권한 확인 창이 열려 있어도 멈춰요 — 그 창은 닫히고 턴이 끝나요.
    - 보드에서 지우기도 한 번 더 눌러야 지워요(`정말 지우기` / `취소`). 24시간이 지난 것처럼 카드와 그 세션에 남은 칸반 답·요청·세션 기록을 지우고 보드로 돌아가요(8). 세션이 살아 있어 다시 생존 신호를 보내면 카드가 다시 나타나요.
11. **질문에 답하기** — 입력 대기(`질문`) 카드의 질문은 보드 아래에 테두리 있는 질문 카드로 늘 펼쳐 그려요. 상세 화면에서는 연 카드의 질문만 상세 아래에 그리고, 다른 세션의 질문은 보드로 돌아가야 보여요. 질문 카드에는 질문마다 머리말(여럿이면 `1/2 · <머리말>`)·문장, 선택지(단일 선택 ○/●, 복수 선택 ☐/☑, 설명 포함), 직접 입력 칸이 있고, 마지막에 `답 보내기` 버튼이 있어요.
    - 선택지를 누르면 고르고, 복수 선택 질문은 다시 누르면 빠져요. 직접 입력을 보내면(Enter) 그 질문의 답이 그 글이 되고 고른 선택지는 지워져요.
    - 보내기는 모든 질문에 답이 있을 때만 받아요. 없으면 어느 질문이 비었는지 한 줄로 보여요. 복수 선택 답은 선택지 순서대로 `, ` 로 이어요.
    - 질문한 세션은 2초 안에 그 답을 받아 질문 화면을 닫고, 사람이 답한 것과 같게 작업을 이어가요. 질문 화면에서 먼저 답하면 그 답이 쓰이고 칸반의 답은 버려요. 답 수가 질문 수와 다르면 버려요(`답 수가 맞지 않아 버렸어요`).
    - 보낸 뒤에는 "보냈어요" 만 보이고, 질문이 끝나면 카드에서 사라져요.
    - 질문 답도 다른 요청처럼 받는 세션에게 전달해요(13). 같은 답을 pane 없이 터미널에서도 보낼 수 있어요. 버전이 섞인 동안 옛 버전 pane 이 보낸 칸반 답도 받아요.
12. **권한 요청에 답하기** — 입력 대기(`권한 요청`) 카드의 `허용`·`거부` 는 그 세션의 권한 확인 창에 사람이 답한 것과 같아요.
    - 권한을 묻는 세션은 창을 띄운 채 칸반의 답을 기다리고, 답이 오면 창을 닫고 허용하거나 거부해요. 거부하면 그 도구는 실행되지 않고 모델은 사람이 칸반에서 거부했다는 이유를 받아요.
    - 창에서 먼저 답하면 그 답이 쓰이고, 칸반은 더 기다리지 않아요.
    - 답은 그 권한 요청 하나에만 들어요. 60초 안에 가져가지 못한 답이나 이미 끝난 요청에 온 답은 버려요.
    - 답에는 보낸 쪽이 있어요 — 칸반 pane·사람의 터미널이거나 메인 에이전트. 메인 에이전트의 답은 칸반 위임의 규칙을 따라야 받아요(`kanban-delegate.md`).
    - 기다림은 30분쯤에서 멈추고, 그 뒤에는 창에서만 답할 수 있어요.
13. **요청 전달** — 보내기·중지·질문 답·결정 답·권한 답은 받는 세션에게 맡기는 요청이에요. 받는 세션은 자기 앞으로 온 요청을 2초 안에, 한 번씩만 가져가요.
    - 프롬프트는 받는 세션이 턴을 돌리지 않을 때만 실행해요. 작업 중이면 실행하지 않고 `작업 중이라 받지 않았어요` 로 끝나요 — 줄 세우지 않아요. 한 번에 여러 개가 와 있으면 가장 먼저 온 하나만 실행해요.
    - 60초 안에 가져가지 못한 요청은 버려요(`시간이 지나 버렸어요`).
    - 중지는 보낸 시점의 턴에만 듣고, 그 턴이 이미 끝났으면 버려요(`끝난 턴이라 버렸어요`).
    - 결정 답은 그 결정 요청에만 들어요. 받는 세션의 결정 요청이 바뀌었거나 사라졌으면 버려요(`끝난 결정이라 버렸어요`). 질문 답은 그 질문이 열려 있을 때만 들어요(`끝난 질문이라 버렸어요`). 결정 요청이 떠 있는 세션에 온 보내기는 결정 답이 아니에요. 일반 프롬프트처럼 다뤄요. 결정 답은 그 결정에 묶인 결정 답 요청으로만 들어가요.
    - 메인 에이전트가 보낸 질문·결정·권한 답은 받는 세션이 칸반 위임 규칙으로 다시 판정하고, 맞지 않으면 버려요(`대리 조건이 맞지 않아 버렸어요`).
    - 사람이 칸반에서 친 글은 그대로, 오케스트레이터가 보낸 글은 앞에 `[칸반 요청 · <보낸 세션> 세션의 오케스트레이터]` 머리말을 붙여 실행해요. 받는 세션의 대화에는 플러그인이 보낸 프롬프트로 보여요.
14. **오케스트레이터** — 메인 오케스트레이터는 같은 보드로 레포별 작업자를 부려요. 어느 레포의 어느 세션에 무엇을 맡길지, 새로 띄울지는 오케스트레이터 skill 이 판단해요.
    - 읽기: 오케스트레이터는 레포(메인 작업 트리)별로 묶은 세션 목록을 읽기만 해요 — 각 세션의 컬럼·작업 디렉토리·권한 모드·할 수 있는 행동·부제목·직전 응답 첫 줄·마지막 요청 전달 결과, 입력 대기면 무엇을 기다리는지, 그리고 위임 세션. 한 컬럼만 골라 읽을 수 있어요. 터미널에서 읽는 보드(15)와 내용이 같아요.
    - 답하기: 입력 대기에 답하는 것은 칸반 위임(`kanban-delegate.md`)을 따라요.
    - 보내기: 쉬는 세션에 일을 맡겨요. 요청 전달(13)을 따라요. 오케스트레이터가 보낸 일은 오케스트레이터가 보낸 것으로 남고, 모델이 사람이 보낸 것으로 꾸며 보내면 막아요.
    - 띄우기: 그 레포의 메인 작업 트리 루트에서만 백그라운드 세션을 띄워요. 같은 체크아웃에서 다른 세션이 돌고 있으면 이름을 준 새 worktree 에 띄워요. 띄운 세션의 짧은 id 를 돌려주고, 그 세션은 모드가 로드되면 보드에 올라와요.
    - 보내기·띄우기는 오케스트레이터 세션의 권한 규칙을 그대로 따라요(기본 모드는 확인, auto 는 분류기, 허용 규칙). 받는 세션의 권한 모드는 보드에 보이지만 보내기를 막지 않아요.
    - 작업자가 끝났는지는 보드를 다시 읽어 알아요.
15. **터미널에서 보기** — 사람과 에이전트는 pane 없이 터미널에서 같은 보드를 읽을 수 있어요. 컬럼(여럿 가능)이나 한 세션만 골라 볼 수 있고, 사람이 읽는 표나 기계가 읽는 형식으로 받아요. 모드가 꺼진 세션은 보이지 않아요(정책 1 과 같음). worker 가 쓴 글 안의 칸반 대기 표지는 표지로 쓸 수 없게 바꿔 보여요.

## 적용 지점

| 지점 | 동작 |
|---|---|
| 모드가 로드된 세션 | 자기 상태(컬럼·진행 상황·기다리는 것·요청과 응답·권한 모드·저장소)를 보드에 알리고 생존 신호를 남겨요(3~6). 자기 앞으로 온 요청·답을 가져가 실행하거나, 실행하지 않을 이유가 있으면 이유와 함께 버려요(11~13) |
| 칸반 pane | 보드를 그리고 카드 상세·질문 카드에서 사람의 답·보내기·중지를 받는 세션에게 전달해요(10~12). 빈 질문이나 없는 선택지가 있는 답은 보내지 않아요. 사라진 세션과 사람이 지운 응답 없음 세션의 카드와 남은 답·요청·기록을 치워요(8·10) |
| 프롬프트 위 띠 | pane 이 열렸는지에 맞춰 열기·닫기 버튼 하나를 보여요. 설문이 있으면 비켜요(2) |
| 터미널 | pane 없이 같은 보드를 읽고, 질문·권한 요청·결정 요청에 답해요(11~13·15) |
| 메인 오케스트레이터 | 보드를 읽고 레포별로 맡길 세션·띄울 레포·맡길 일을 정해 보내거나 띄워요(14) |
| 칸반 위임 세션 | 다른 세션의 입력 대기를 모아 대신 답하거나 사용자에게 물어 전달해요(`kanban-delegate.md`) |

## 실패 처리

- `atelier` CLI 가 없거나 실패함 → pane 에 이유 한 줄과 `/atelier:update` 안내만 그려요. 세션 동작에는 영향이 없어요.
- `/kanban` 에서 `atelier` CLI 를 찾지 못하거나 실패함 → 인자가 있든 없든 pane 을 열고 닫지 않고, 이유와 `/atelier:update` 안내를 답해요.
- 기록을 읽지 못함(다른 버전이 쓴 기록·깨진 기록) → 그 카드만 빼요. 그 기록은 지우지 않아요.
- 터미널에서 읽을 세션 기록을 쓰지 못함 → 다음 기록 때 다시 써요. 그동안 터미널의 보드는 읽지 못한 세션을 빼요.
- 새 pane 의 질문 답은 옛 버전 모드의 세션이 받지 못하고 버려요(`/atelier:update` 뒤 그 세션을 다시 시작하면 받아요).
- 옛 버전 pane 의 권한 허용·거부는 받지 않아요 → 그 pane 에 업데이트 안내(`/atelier:update`)가 보여요. 그 세션 창에서 직접 답하면 돼요.
- 기록 쓰기 실패 → 다음 이벤트·생존 신호 때 다시 써요. 원래 이벤트는 막지 않아요.
- 턴 끝 응답을 판단하는 모델 호출이 실패함 → 결정 요청을 남기지 않아요. 그 세션은 쉬는 중이에요. 턴 끝은 막지 않아요.
- pane 의 답·보내기·중지가 실패함(CLI 없음·거부) → pane 에 이유 한 줄만 보이고 아무것도 남기지 않아요. 입력한 글은 그대로 남아요.
- 이미 끝난 질문에 칸반 답이 늦게 옴 → 받는 세션이 가져갈 때 버려요(`끝난 질문이라 버렸어요`).
- 읽을 수 없는 요청 → 가져갈 때 버려요.
- 새 세션 띄우기 실패(`claude` 없음·로그인 안 됨·루트가 아님·worktree 이름이 잘못됨) → 이유를 돌려주고 아무 세션도 띄우지 않아요.

## 제약 조건

- 권한 확인에 답한 순간을 알리는 이벤트가 없어요. 그래서 답한 뒤 Claude Code 가 spinner 를 다시 그리는 것으로 작업 재개를 판단해요. spinner 를 그리지 않는 환경(`claude -p`·SDK 호스트)에서는 도구가 끝날 때까지 입력 대기로 남고, 창이 열린 동안에도 spinner 를 그리는 화면에서는 권한 요청이 곧바로 작업 중으로 보일 수 있어요. 질문(AskUserQuestion)은 이 제약이 없어요.
- 같은 머신의 세션만 공유해요(세션 기록과 요청이 이 머신에만 있어요).
- 평문 질문의 결정 요청은 모델의 판단이라 틀릴 수 있어요. 답을 기다리는 세션이 쉬는 중으로, 끝난 세션이 결정 요청으로 보일 수 있어요. 메인 턴이 끝날 때마다 작은 모델을 한 번 불러요.
- 따로 띄운 세션끼리는 이어지지 않아요. 한 세션이 다른 세션에 일을 보내고(SendMessage 등) 답을 기다려도, 엔진이 알려 주는 백그라운드 작업이 아니라서 두 세션 모두 턴이 끝나면 쉬는 중이에요.
- 카드에서 그 세션 화면으로 이동하는 기능은 없어요. 모드가 다른 세션으로 화면을 바꿀 수단이 없어요.
- 권한 답은 요청을 받을 수 있는 세션(atelier CLI 가 있고 자기 앞으로 온 요청을 찾을 수 있는 세션)에서만 받아요. 그렇지 않은 세션의 권한 요청 카드에는 허용·거부가 없어요.
- 질문이 열린 채로 모드가 다시 로드되면, 그 질문은 칸반에서 답해도 받지 못해요. 질문 화면에서 답하면 돼요. 메인 에이전트가 보낸 답도 같아요.
- 작업 중 상세는 메인 대화의 도구만 보여요. 하위 에이전트가 하는 일은 `Agent` 한 줄로만 보여요.
- 백그라운드 일은 턴 끝에 엔진이 알려 주는 목록과 생존 신호(30초) 때 본 에이전트 상태로만 알아요. 그래서 팀원이 일을 시작하거나 멈춘 것은 최대 30초 늦게 보여요. Esc 로 턴을 끊으면 엔진이 그 목록을 주지 않아서, 그 턴 뒤에는 일하는 에이전트가 있을 때만 작업 중으로 보여요(Workflow 만 남았으면 쉬는 중).
