# 세션 칸반

> 이 머신에서 atelier 가 켜진 Claude Code 세션 전체를 한 pane 의 칸반으로 보여줘요. 세션 하나가 카드 하나이고, 컬럼은 세션이 지금 무엇을 기다리는지예요. 카드를 열면 그 컬럼에 맞는 상세와 행동이 나와요 — 질문에 답하고, 결정 요청에 답하고, 쉬는 세션에 일을 맡기고, 일하는 세션을 멈춰요. 오케스트레이터는 같은 보드를 읽어 레포별로 작업자를 부려요.

## 역할

여러 세션을 동시에 돌릴 때 "어느 세션이 내 답을 기다리는지", "어느 세션이 아직 일하는지·무엇을 하는지", "어느 세션이 쉬고 있고 직전에 무엇을 했는지", "어느 세션이 죽었는지"를 한눈에 보게 하고, 그 세션으로 가지 않고 답하거나 일을 맡기거나 멈추게 해요.

## 정책

1. **대상** — atelier 모드가 로드된 세션만 보여요. 모드가 없는 세션·다른 머신의 세션은 대상이 아니에요. `claude --bg` 로 띄운 백그라운드 세션도 모드가 로드되면 대상이에요.
2. **열기** — `/kanban` 으로 pane 을 열고, 다시 입력하면 닫아요. 넓은 화면은 대화 옆, 좁은 화면은 프롬프트 위에 놓여요.
3. **컬럼** — 순서는 고정이에요: 입력 대기 → 작업 중 → 쉬는 중 → 응답 없음. 빈 컬럼도 보여요.
   - **입력 대기**: 사람의 답을 기다려요. 카드에 무엇을 기다리는지 표시해요.
     - `권한 요청: <도구>` — 권한 확인 창.
     - `질문` — AskUserQuestion 질문 창. 질문이 열려 있는 동안은 화면이 무엇을 그리든 입력 대기예요. 질문 뒤에 프롬프트·도구 결과·턴 끝·다른 도구의 권한 요청이 오면 그 질문은 끝난 것으로 봐요.
     - `결정 요청` — 턴이 끝나면서 사람에게 결정을 물었어요(데스크톱의 턴 끝 결정 카드, `WrapUp` 의 질문). 다음 턴이 시작되면 사라져요.
     - `입력 요청` — MCP 입력 요청.
   - **작업 중**: 프롬프트를 받았거나 도구를 실행하고 있어요. 권한 확인·질문에 답한 직후부터 작업 중이에요(칸반에서 답한 경우 포함).
   - **쉬는 중**: 턴이 끝나 다음 프롬프트를 기다려요. 막 시작한 세션도 여기예요.
   - **응답 없음**: 세션 프로세스의 생존 신호가 2분 넘게 끊겼어요(비정상 종료·멈춤). 직전 컬럼과 상관없이 여기로 옮겨요.
4. **카드** — 이름, 그 컬럼에 머문 시간, 부제목을 보여요. pane 을 연 세션 자신은 `▶` 로 표시해요. 진행 상황이 있으면 한 줄, 쉬는 중이면 `직전: <직전 응답 첫 줄>` 을 한 줄 더 보여요.
   - 이름은 저장소 이름이에요 — 원격 저장소 주소의 이름, 없으면 메인 작업 트리 디렉토리 이름, 저장소가 아니면 작업 디렉토리 이름. worktree 에서 도는 세션도 저장소 이름으로 보여요.
   - 부제목은 세션 제목, 없으면 첫 프롬프트, 그것도 비면 마지막 프롬프트를 한 줄로 접어 60자로 잘라요.
   - 프롬프트로는 사람이 친 것(대화 입력·원격 제어·SDK 호스트)과 칸반에서 보낸 것만 기록해요. 백그라운드 작업 알림·예약 실행 같은 자동 프롬프트는 작업 중으로 바꾸기만 하고 기록하지 않아요.
   - 엔진이 프롬프트에 붙인 `<system-reminder>` 안내문, 칸반 요청 머리말(12), 터미널 제어 문자는 보이지 않아요.
5. **진행 상황** — 응답 없음이 아닌 카드에 `할 일 <완료>/<전체> · <진행 중인 할 일>` 을, 작업 중 카드에는 이어서 `▸ <도구>: <대상>` 을 보여요.
   - 할 일은 세션의 Task 목록(`TaskCreate`·`TaskUpdate`)이 있으면 그것을, 없으면 `TodoWrite` 목록을 세요. 지운 할 일은 세지 않아요. 할 일이 없으면 이 부분을 빼요.
   - 진행 중인 할 일은 첫 번째 진행 중 항목의 진행형 문구(없으면 제목)이고, 40자로 잘라요.
   - 도구 대상은 도구 입력의 설명·파일·패턴·주소·명령 순으로 처음 있는 값이에요. 파일 경로는 파일 이름만, 40자로 잘라요. 턴이 끝나면 지워요.
6. **머문 시간** — 지금 컬럼에 들어온 시각부터 세요. 같은 상태가 이어지는 동안(도구를 여러 번 실행하는 동안 등)은 다시 세지 않아요. 질문은 질문이 열린 시각부터, 결정 요청은 턴이 끝난 시각부터 세요. 응답 없음은 마지막 생존 신호부터 세요.
7. **정렬** — 입력 대기·작업 중은 오래 기다린 세션이 위, 쉬는 중·응답 없음은 최근 세션이 위예요.
8. **사라짐** — 세션이 정상 종료하면 카드가 바로 사라져요. 생존 신호가 24시간 넘게 없으면 그때 사라져요. 그 세션에 남은 칸반 답·요청도 같이 지워요.
9. **갱신** — pane 이 열려 있는 동안 2초마다 다시 그려요. 닫혀 있으면 보드를 읽지 않아요.
10. **카드 상세** — 카드 제목을 누르면 보드 아래에 그 카드의 상세가 펼쳐지고, 다시 누르면 접혀요. 한 번에 한 카드만 펼쳐요. 컬럼을 세로로 쌓는 좁은 pane 에서는 상세가 보드 자리를 대신하고 `뒤로` 로 돌아가요.

    | 컬럼 | 상세 | 행동 |
    |---|---|---|
    | 입력 대기 · 권한 요청 | 기다리는 것(`<도구>: <명령·파일·주소…>`), 요청, 기다리기 직전 응답 | 중지 |
    | 입력 대기 · 질문 | 요청, 기다리기 직전 응답 | 질문 답하기(11), 중지 |
    | 입력 대기 · 결정 요청 | 요약, 질문, 답 버튼, 요청 | 답 버튼 누르기, 직접 입력해 보내기 |
    | 작업 중 | 요청, 할 일 목록(✓ 완료 · ▸ 진행 · · 대기), 최근 도구 5개와 각 경과 시간 | 중지 |
    | 쉬는 중 | 직전 요청, 직전 응답 | 입력해 보내기 |
    | 응답 없음 | 마지막 요청, 마지막 응답 | 없음 |

    - 요청은 300자, 응답은 앞 6줄(줄마다 200자), 기다리는 것은 120자까지 보여요. 할 일이 8개를 넘으면 완료한 것을 `✓ 완료 <n>개` 한 줄로 접고, 남은 것을 8개까지 보여요.
    - 기다리기 직전 응답은 질문·권한 요청이 시작될 때 그 세션의 마지막 응답이에요.
    - 보내기는 빈 글을 받지 않아요. 보낸 뒤에는 "보냈어요" 를, 받은 세션이 처리한 뒤에는 `보낸 요청: <결과> · <경과>` 를 보여요.
    - 중지는 한 번 더 눌러야 보내요(`정말 중지` / `취소`). 권한 확인 창이 열려 있어도 멈춰요 — 그 창은 닫히고 턴이 끝나요.
11. **질문에 답하기** — 입력 대기(`질문`) 카드의 질문은 보드 아래에 늘 펼쳐 그려요: 질문마다 머리말·문장, 선택지(설명 포함), 직접 입력 칸, 그리고 보내기 버튼.
    - 선택지를 누르면 고르고, 복수 선택 질문은 다시 누르면 빠져요. 직접 입력을 보내면(Enter) 그 질문의 답이 그 글이 되고 고른 선택지는 지워져요.
    - 보내기는 모든 질문에 답이 있을 때만 받아요. 없으면 어느 질문이 비었는지 한 줄로 보여요. 복수 선택 답은 선택지 순서대로 `, ` 로 이어요.
    - 질문한 세션은 2초 안에 그 답을 받아 질문 화면을 닫고, 사람이 답한 것과 같게 작업을 이어가요. 질문 화면에서 먼저 답하면 그 답이 쓰이고 칸반의 답은 버려요.
    - 보낸 뒤에는 "보냈어요" 만 보이고, 질문이 끝나면 카드에서 사라져요.
12. **요청 전달** — 보내기·중지는 받는 세션에게 맡기는 요청이에요. 받는 세션은 2초마다 자기 앞으로 온 요청을 한 번씩만 가져가요.
    - 프롬프트는 받는 세션이 턴을 돌리지 않을 때만 실행해요. 작업 중이면 실행하지 않고 `작업 중이라 받지 않았어요` 로 끝나요 — 줄 세우지 않아요. 한 번에 여러 개가 와 있으면 가장 먼저 온 하나만 실행해요.
    - 60초 안에 가져가지 못한 요청은 버려요(`시간이 지나 버렸어요`).
    - 중지는 보낸 시점의 턴에만 듣고, 그 턴이 이미 끝났으면 버려요(`끝난 턴이라 버렸어요`).
    - 사람이 칸반에서 친 글은 그대로, 오케스트레이터가 보낸 글은 앞에 `[칸반 요청 · <보낸 세션> 세션의 오케스트레이터]` 머리말을 붙여 실행해요. 받는 세션의 대화에는 플러그인이 보낸 프롬프트로 보여요.
13. **오케스트레이터** — 메인 오케스트레이터는 같은 보드로 레포별 작업자를 부려요. 어느 레포의 어느 세션에 무엇을 맡길지, 새로 띄울지는 오케스트레이터 skill 이 판단해요.
    - 읽기: 모드 툴 `kanban_board`(읽기 전용)가 레포(메인 작업 트리)별로 묶은 세션 목록을 줘요 — 각 세션의 컬럼·작업 디렉토리·권한 모드·할 수 있는 행동·부제목·직전 응답 첫 줄·마지막 요청 전달 결과.
    - 보내기: `atelier kanban send --from agent` 로 쉬는 세션에 맡겨요. 요청 전달(12)을 따라요.
    - 띄우기: `atelier kanban spawn --cwd <메인 작업 트리 루트>` 로 그 레포에 백그라운드 세션을 띄워요. 같은 체크아웃에서 다른 세션이 돌고 있으면 `--worktree <이름>` 으로 새 worktree 에 띄워요. 띄운 세션의 짧은 id 를 돌려주고, 그 세션은 모드가 로드되면 보드에 올라와요.
    - 보내기·띄우기는 오케스트레이터 세션의 권한 규칙을 그대로 따라요(기본 모드는 확인, auto 는 분류기, 허용 규칙). 받는 세션의 권한 모드는 보드에 보이지만 보내기를 막지 않아요.
    - 작업자가 끝났는지는 보드를 다시 읽어 알아요.

## 적용 지점

| 지점 | 동작 |
|---|---|
| 각 세션의 모드 | 프롬프트·턴 시작/끝·권한 요청·알림·도구 결과·spinner 재표시·종료를 사실 그대로 세션별로 기록하고, 30초마다 생존 신호를 남겨요. 도구 호출·할 일·열린 질문·결정 요청·마지막 요청과 응답·권한 모드·저장소 위치도 기록해요. 열린 질문의 칸반 답과 자기 앞으로 온 요청을 2초마다 가져가요 |
| atelier CLI (보드 판정) | 기록 묶음과 현재 시각·임계값을 받아 컬럼별 카드(진행 상황·상세·행동·열린 질문 포함), 레포별 묶음, 지울 세션 목록을 돌려줘요. 판정은 전부 여기서 해요 |
| atelier CLI (답 만들기) | 질문과 고른 선택지·직접 입력을 받아 질문 순서의 답 목록을 돌려주거나, 빈 질문·없는 선택지를 거부해요 |
| atelier CLI (요청) | 보내기·중지 요청을 받는 세션 앞으로 남기고, 받는 세션이 가져갈 때 무엇을 실행할지(만료·작업 중·끝난 턴) 판정해요. 새 백그라운드 세션을 메인 작업 트리 루트에서만 띄워요 |
| pane | 받은 보드를 그리고, 카드 상세의 입력·버튼을 요청으로, 질문의 선택을 답으로 바꿔요. 지울 세션의 기록과 남은 답·요청을 지워요 |
| 오케스트레이터 skill | 보드를 읽고 레포별로 맡길 세션·띄울 레포·맡길 일을 정해 요청 CLI 를 불러요 |

## 실패 처리

- `atelier` CLI 가 없거나 실패함 → pane 에 이유 한 줄과 `/atelier:update` 안내만 그려요. 세션 동작에는 영향이 없어요.
- 기록을 읽지 못함(다른 버전이 쓴 기록·깨진 기록) → 그 카드만 빼요. 그 기록은 지우지 않아요.
- 기록 쓰기 실패 → 다음 이벤트·생존 신호 때 다시 써요. 원래 이벤트는 막지 않아요.
- 답 만들기·보내기·중지가 실패함(CLI 없음·거부) → pane 에 이유 한 줄만 보이고 아무것도 남기지 않아요. 입력한 글은 그대로 남아요.
- 이미 끝난 질문에 칸반 답이 늦게 써짐 → 아무도 읽지 않고, 그 세션이 사라질 때 지워져요.
- 읽을 수 없는 요청 → 가져갈 때 버려요.
- 새 세션 띄우기 실패(`claude` 없음·로그인 안 됨·루트가 아님·worktree 이름이 잘못됨) → 이유를 돌려주고 아무 세션도 띄우지 않아요.

## 제약 조건

- 권한 확인에 답한 순간을 알리는 이벤트가 없어요. 그래서 답한 뒤 Claude Code 가 spinner 를 다시 그리는 것으로 작업 재개를 판단해요. spinner 를 그리지 않는 환경(`claude -p`·SDK 호스트)에서는 도구가 끝날 때까지 입력 대기로 남고, 창이 열린 동안에도 spinner 를 그리는 화면에서는 권한 요청이 곧바로 작업 중으로 보일 수 있어요. 질문(AskUserQuestion)은 이 제약이 없어요.
- 같은 머신의 세션만 공유해요(모드 저장소와 요청이 머신 로컬이에요).
- 카드에서 그 세션 화면으로 이동하는 기능은 없어요. 모드가 다른 세션으로 화면을 바꿀 수단이 없어요.
- 칸반에서 권한 확인에 허용·거부로 답할 수는 없어요. 열린 권한 창을 바깥에서 닫는 수단이 없어서, 그 세션에서 답하거나 칸반에서 중지해요.
- 질문이 열린 채로 모드가 다시 로드되면, 그 질문은 칸반에서 답해도 받지 못해요. 질문 화면에서 답하면 돼요.
- 작업 중 상세는 메인 대화의 도구만 보여요. 하위 에이전트가 하는 일은 `Agent` 한 줄로만 보여요.
