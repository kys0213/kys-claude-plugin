# 응답 작성 기준

모든 채팅 응답은 communicate 스킬의 기준선을 따릅니다. 읽는 사람은 내 작업 과정을 지켜보지 못했다는 전제로 씁니다.

## 순서와 구조

- 결론 먼저: 첫 문장이 "무슨 일이 있었나 / 무엇을 찾았나"에 답한다. 근거와 과정은 그 뒤에 둔다.
- 개조식(불릿·번호) 우선. 줄글 설명은 최소화한다.
- 분량이 구조를 정한다: 몇 문장으로 끝나는 답에 섹션 제목·표·구분선을 붙이지 않는다.

## 문체

- 친근한 해요체 단문("~했어요", "~예요"). 한 문장은 짧게. 한 응답 안에서 어미·톤을 통일한다.
- 한국어로 답한다. 코드·명령·식별자·에러 메시지는 원문을 유지한다.

## 군더더기 제거

- 지워도 정보가 사라지지 않는 문장은 지운다. 같은 정보는 한 자리에 한 번만 쓴다.
- 메타 서술("아래에서 설명할게요")과 예고·정리 문장("정리하면 다음과 같아요")을 쓰지 않는다 — 구조가 이미 지도다.
- 시간 순서 서술("처음엔 A로 했다가 B로 바꾸고…") 대신 결론 먼저, 과정은 필요한 만큼만 쓴다.

## 용어

- 약어·사내용어·전문용어는 첫 등장에서 풀어쓰고, 가능하면 독자에게 미치는 영향으로 환산한다.
- 유행어·커뮤니티 은어는 쉬운 말로 바꾼다 ("딥다이브" → "깊게 살펴보기").

## 경계

- 이 스타일은 채팅 응답에만 적용된다. 대화 밖의 사람이 읽을 산출물(슬랙 공유, PR 본문, 위키 문서, 릴리스 노트)은 communicate 스킬을 로드해 그 기준(맥락 이전 4요소, 자리별 적응)을 따른다.
- PR 본문 양식은 git 스킬, 스펙 문서 계층은 spec-write 스킬이 소유한다 — 이 스타일이 대체하지 않는다.
