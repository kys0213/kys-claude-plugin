# communicate

**내가 아는 것을 그 과정을 못 본 사람에게 옮기는** 글쓰기 기준입니다. 보고서·채팅 답변·위키 문서·PR 설명은 포장이 다를 뿐 같은 문제를 풉니다 — *읽는 사람은 우리가 나눈 대화를 보지 못했다.*

고정 양식을 강제하지 않습니다. 어디에 놓든 적용되는 **기본값 · 맥락 이전 · 읽기 수준 · 문체**를 제공하고, 놓이는 자리에 따라 달라지는 부분은 `references/delivery-context.md` 로 분리합니다.

이 skill 이 소유하는 것은 **무엇을 어떤 문체·깊이로 쓸 것인가의 기준**입니다. 실제 파일 Write 는 `orchestrator` skill 이 위임하는 sub-agent 가 수행하며, 메인 에이전트는 Write 를 위임할 뿐 직접 실행하지 않습니다.

## 기본값 (자리와 무관)

PR 본문 규칙을 **모든 글의 기본값으로 승격**한 것입니다. 놓이는 자리가 바뀌면 포장이 바뀔 뿐 이 넷은 그대로 갑니다.

| 항목 | 기본값 |
|---|---|
| 독자 | IT 특성화 고등학생도 이해할 수 있는 수준 — 약어·사내용어는 풀어쓴다 |
| 문체 | 친근한 해요체 단문 ("~했어요", "~예요"). 한 문장은 짧게 |
| 정보 전달 | 개조식(불릿·번호) 우선. 줄글 설명은 최소화 |
| 언어 | 한국어. 코드·명령·식별자는 원문 유지 |

- **격식이 필요한 대외·공식 문서**만 평서체("~했다")로 바꾼다. 어떤 문체를 골랐든 한 문서 안에서는 통일한다.
- PR 본문은 이 기본값이 고정 양식을 만난 경우이며 **섹션 4단이 고정**이다 — 정확한 양식은 `git` 스킬의 `references/cli-reference.md` 가 단일 출처다.

## 작문 철학

1. **신뢰 우선** — 글의 가치는 읽는 사람이 그 내용을 *믿고 의사결정에 쓸 수 있는가*에 달렸다. 모든 선택(문체·용어·구조)은 신뢰성과 이해 속도를 높이는 방향으로 한다.
2. **결론 먼저 (BLUF)** — 핵심을 맨 앞에 둔다. 첫 문단만 읽어도 결정을 내릴 수 있어야 한다.
3. **사실과 판단 분리** — 관찰한 사실, 그에 대한 해석, 권고를 구분해 쓴다. 추정은 "추정", 미확인은 "미확인"으로 표시한다.
4. **근거는 검증 가능하게** — 주장에는 출처(경로·라인·명령 출력·수치·링크)를 붙인다. "잘 된다"가 아니라 "테스트 12건 통과(`cargo test`)"로 쓴다.

## 맥락 이전 (Context Handoff)

가장 자주 실패하는 지점입니다. 에이전트와 수십 턴을 주고받으며 쌓인 전제·별명·기각된 선택지는 **전부 내 쪽에만** 있습니다. 읽는 사람에게는 결과물만 도착합니다.

### 옮겨야 할 네 가지

PR 본문의 4단(왜 / 무엇을 / 어떻게 / 확인 방법)이 이 네 가지의 원형입니다. 놓이는 자리가 달라도 질문은 같습니다.

| 질문 | 내용 | 빠뜨렸을 때 |
|---|---|---|
| **왜** | 계기·문제 상황·배경 | 읽는 사람이 "이걸 왜 지금?"에서 막힌다 |
| **무엇을** | 실제로 바뀐 것 (파일·모듈·동작 단위) | 변경 범위를 각자 추측한다 |
| **어떻게** | 고른 접근과 **버린 선택지 + 이유** | 나중에 "왜 이렇게 했지?"가 복원 불가능해진다 |
| **확인 방법** | 읽는 사람이 따라할 수 있는 검증 단계 | 믿을지 말지를 판단할 수 없다 |

- 자리가 좁아 넷을 다 못 쓰면 **줄이되 순서는 지킨다** — "왜"가 없는 공유는 거의 항상 되묻는 질문을 부른다.
- **버린 선택지는 특히 잘 사라진다.** 대화에서 길게 논의하고 접은 안은 결과물에 흔적이 없다. 한 줄이라도 남긴다.

### 대화 잔재 제거

| 잔재 | 문제 | 고침 |
|---|---|---|
| 지시어 ("아까 그 이슈", "그 파일") | 독자에겐 가리킬 대상이 없다 | 이름·경로·링크로 치환 |
| 대화에서만 쓰던 별명 | 무엇인지 모른다 | 정식 이름 + 한 줄 설명 |
| 합의된 전제 ("어차피 그건 안 쓰니까") | 합의 자체를 못 봤다 | 전제를 문장으로 드러낸다 |
| 시간 순서 서술 ("처음엔 A로 했다가 B로 바꾸고…") | 과정은 독자의 관심사가 아니다 | 결론 먼저, 과정은 필요한 만큼만 |

> **자가 점검**: 쓴 글을 위에서부터 읽으며 "이 문장을 이해하려면 우리 대화를 봤어야 하는가?"를 묻는다. 하나라도 걸리면 그 문장은 아직 옮겨지지 않은 것이다.

## 읽기 수준 (Reading Level)

기본값은 "IT 특성화 고등학생이 읽고 이해할 수 있는가"입니다. 핵심 기법은 **용어를 설명하지 말고 영향을 말하는 것**입니다.

```
❌ N+1 문제가 있었어요                                       # 모르면 그냥 막힌다
△  반복 조회로 쿼리가 행 수만큼 발생하는 N+1 문제가 있었어요    # 설명은 붙었지만 여전히 남 얘기
✅ 목록 100개를 열면 DB에 101번 물어보고 있었어요. 지금은 2번이에요
```

- **영향으로 환산한다**: 무슨 개념인지가 아니라 *무슨 일이 벌어지는지*를 쓴다. 가능하면 수치로.
- **과잉 해설 금지**: 청중이 당연히 아는 용어(개발자에게 "함수", "커밋")는 해설하지 않는다 — 신뢰와 가독성을 함께 떨어뜨린다.
- **비유는 정확할 때만**: 틀린 비유는 무해설보다 나쁘다. 독자가 그 비유로 다음 판단을 내리기 때문이다.

### 용어 처리 기준

| 상황 | 처리 |
|---|---|
| 청중이 모를 수 있는 전문용어 | **첫 등장 시 한 번** 짧게 풀고 이후 그대로 사용 |
| 약어·이니셜리즘 | 처음에 풀어쓰고 괄호로 약어 — "지속적 통합(CI)", 이후 "CI" |
| 프로젝트 내부 코드명·은어 | 외부 청중이면 일반 용어로 바꾸거나 정의를 단다 |
| 한 개념을 가리키는 여러 단어 | **하나로 통일**한다. 동의어 혼용은 같은 것을 다른 것으로 오해하게 만든다 |

- **정의 위치**: 용어가 1~2개면 인라인(괄호)으로, 여러 개면 앞이나 끝에 **용어집**으로 모은다.

## 문체 (Style)

### 문장
- **한 문장 한 정보.** 접속사로 이어붙인 긴 문장은 끊는다.
- **능동형 우선.** "수정이 이루어졌다" → "X를 수정했어요".
- **수동태·이중부정·완곡어법 지양.** "되지 않는 것은 아니다" → "돼요" 또는 "안 돼요".
- 표·목록으로 표현되는 정보는 산문으로 늘어놓지 않는다.
- **객관적·중립적으로.** 해요체라도 감정·과장("놀랍게도", "완벽하게")을 빼고 사실로 말한다. 자신 없는 내용은 단정하지 말고 불확실성을 드러낸다("~인 것 같아요", "미확인").

### 어미·시제 (개조식 vs 서술식)
- 한 문서 안에서 **어미를 통일**한다. 짧은 항목 나열은 개조식(명사·"~함"), 설명이 필요한 본문은 서술식(완전한 문장). 한 섹션에서 둘을 섞지 않는다.
- 완료된 일은 과거형, 현재 상태는 현재형, 계획은 미래형으로 시제를 사실에 맞춘다.
- 예: "인증 모듈을 구현하였고, 이로 인해 보안성이 크게 향상되는 결과가 도출되었음" → "인증 모듈을 구현했어요. 로그인 실패율이 0건으로 떨어졌어요(테스트 12건)".

## 청중별 적응

**읽는 사람이 무엇을 결정하려 하는지**에 맞춰 무엇을 앞에 둘지 정한다.

| 청중 | 우선 정보 | 깊이 |
|---|---|---|
| 의사결정자 | 결론 · 영향 · 선택지 · 비용 | 근거는 요약, 상세는 부록·링크 |
| 동료 개발자 | 변경 지점 · 근거 · 검증 방법 | 경로·라인 수준까지 |
| 다른 팀 · 비개발 직군 | 무엇이 달라지는가 · 언제부터 · 내가 할 일 | 내부 구현은 생략, 영향만 |
| 미래의 나/팀 (기록용) | 맥락 · 결정 이유 · 당시 제약 | 재현 가능할 만큼 |

- 같은 사실도 청중에 따라 **분량과 순서**를 바꾼다. 의사결정자에게 diff를 늘어놓거나, 개발자에게 "잘 됨"만 보내지 않는다.
- 청중이 불명확하면 가장 좁은 청중(가장 많은 맥락이 필요한 쪽)을 기준으로 쓰고, 머리에 대상 청중을 한 줄 명시한다.

## 전달 맥락 적응

놓이는 자리는 **포장**을 바꿀 뿐 위의 기본값·맥락 이전·읽기 수준은 그대로 간다.

판단 기준은 **도구가 아니라 성질**이다 — 도구 이름은 바뀌지만 성질은 바뀌지 않는다. 흘러가는가 남는가, 되물을 수 있는가, 상대가 무엇을 해야 하는가, 누가 읽는지 아는가, 양식이 정해져 있는가, 서식이 살아남는가. 이 축들이 길이·구조·서식·질문 위치를 결정한다.

| 파일 | 언제 읽을지 |
|---|---|
| `references/delivery-context.md` | 놓을 자리가 정해졌을 때 — 성질 축별 판단 기준, 판단 순서, 조합 예시, 자리 선택 자체가 틀리는 경우 |
