# communicate

**내가 아는 것을 그 과정을 못 본 사람에게 옮기는** 글쓰기 기준입니다. 보고서·채팅 답변·위키 문서·PR 설명은 포장이 다를 뿐 같은 문제를 풉니다 — *읽는 사람은 우리가 나눈 대화를 보지 못했다.*

고정 양식을 강제하지 않습니다. 이 문서는 **어디에 놓든 유지되는 기준선**과, 글이 가장 자주 실패하는 두 지점만 담습니다 — 나만 아는 배경을 글에 옮기지 못하는 것(§맥락 이전)과 지워도 되는 문장을 남겨 글이 길어지는 것(§군더더기 제거)입니다. 적용 상세와 자리별 적응은 references 로 분리합니다.

이 skill 은 **무엇을 어떤 문체·깊이로 쓸지의 기준**만 소유합니다. 실제 파일 Write 는 `orchestrator` skill 이 위임하는 sub-agent 가 수행합니다.

**채팅 답변은 위임하지 않습니다** — Write 가 없으니 기준만 적용해 그 자리에서 답합니다. "쉽게 설명해줘"에 sub-agent 를 띄우지 마세요.

## 기준선 (자리와 무관 — 단일 출처)

PR 본문 규칙을 **모든 글의 기본값으로 승격**한 것입니다. 자리가 바뀌면 포장만 바뀌고 이 다섯은 그대로 갑니다. `templates/claude-md/CLAUDE.md` 의 요약본과 어긋나면 이 절이 우선합니다.

| 항목 | 기본값 |
|---|---|
| 독자 | IT 특성화 고등학생도 이해할 수 있는 수준 — 약어·사내용어는 풀어쓴다 |
| 문체 | 친근한 해요체 단문 ("~했어요", "~예요"). 한 문장은 짧게 |
| 정보 전달 | 개조식(불릿·번호) 우선. 줄글 설명은 최소화 |
| 분량 | 지워도 정보가 사라지지 않는 문장은 지운다. 같은 정보는 한 자리에 한 번만 |
| 언어 | 한국어. 코드·명령·식별자는 원문 유지. 유행어는 쉬운 말로 바꾼다 ("딥다이브" → "깊게 살펴보기") |

- 격식이 필요한 대외·공식 문서만 평서체("~했다")로 쓴다. 어떤 문체든 한 문서 안에서는 통일한다.
- PR 본문은 **섹션 4단이 고정**이다. 양식은 `git` 스킬의 `references/cli-reference.md` 가 단일 출처다.

## 외부 전송 2단계 (draft → send)

Slack·Confluence·이슈 코멘트처럼 **이 대화 밖으로 나가는 쓰기**는 항상 2단계로 진행해요. 전송은 되돌리기 어렵고, 잘못된 스레드나 오류 있는 내용이 나가면 정정 비용이 글쓰기 비용보다 커요.

1. **draft 먼저**: 전송하지 않고 draft를 사용자에게 제시해요. 주장에는 인용 가능한 근거(citation — 링크·파일 경로·메시지 출처)를 붙여요.
2. **명시적 승인 후 전송**: "보내줘"·"발행해줘" 같은 명시적 승인이 있을 때만 전송해요.

- "정리해줘"·"답변 만들어줘"류 요청의 기본값은 **draft**예요 — 글을 만들어 달라는 요청이지 전송 승인이 아니에요.
- 어디로 보내는지(채널·스레드·페이지)가 확정되지 않았으면 draft 단계에서 함께 확인해요.
- 위임된 sub-agent에도 그대로 적용돼요 — draft 작성 위임에 전송 권한을 얹지 않아요.

## 맥락 이전 (Context Handoff)

가장 자주 실패하는 지점입니다. 대화하며 쌓인 전제·별명·기각된 선택지는 **전부 내 쪽에만** 있습니다. 읽는 사람에게는 결과물만 도착합니다.

### 옮겨야 할 네 가지

PR 본문의 4단(왜 / 무엇을 / 어떻게 / 확인 방법)이 원형입니다. 자리가 달라도 질문은 같습니다.

| 질문 | 내용 | 빠뜨렸을 때 |
|---|---|---|
| **왜** | 계기·문제 상황·배경 | 읽는 사람이 "이걸 왜 지금?"에서 막힌다 |
| **무엇을** | 실제로 바뀐 것 (파일·모듈·동작 단위) | 변경 범위를 각자 추측한다 |
| **어떻게** | 고른 접근과 **버린 선택지 + 이유** | 나중에 "왜 이렇게 했지?"가 복원 불가능해진다 |
| **확인 방법** | 읽는 사람이 따라할 수 있는 검증 단계 | 믿을지 말지를 판단할 수 없다 |

- 자리가 좁으면 **줄이되 순서는 지킨다** — "왜"가 없는 공유는 거의 항상 되묻는 질문을 부른다.
- **버린 선택지는 특히 잘 사라진다.** 길게 논의하고 접은 안은 결과물에 흔적이 없다. 한 줄이라도 남긴다.

### 대화 잔재 제거

| 잔재 | 문제 | 고침 |
|---|---|---|
| 지시어 ("아까 그 이슈", "그 파일") | 독자에겐 가리킬 대상이 없다 | 이름·경로·링크로 치환 |
| 대화에서만 쓰던 별명 | 무엇인지 모른다 | 정식 이름 + 한 줄 설명 |
| 합의된 전제 ("어차피 그건 안 쓰니까") | 합의 자체를 못 봤다 | 전제를 문장으로 드러낸다 |
| 시간 순서 서술 ("처음엔 A로 했다가 B로 바꾸고…") | 과정은 독자의 관심사가 아니다 | 결론 먼저, 과정은 필요한 만큼만 |

> **자가 점검**: 위에서부터 읽으며 "이 문장을 이해하려면 우리 대화를 봤어야 하는가?"를 묻는다. 걸리는 문장은 아직 옮겨지지 않은 것이다.

## 군더더기 제거 (Decluttering)

맥락 이전 다음으로 자주 실패하는 지점입니다. 4요소를 채우라는 것은 정보를 빠뜨리지 말라는 뜻이지 길게 쓰라는 뜻이 아닙니다 — 각 요소는 한두 문장이면 충분할 때가 많습니다.

| 군더더기 | 왜 생기는가 | 고침 |
|---|---|---|
| 메타 서술 ("이 문서는 ~을 정리한 거예요", "아래에서 설명할게요") | 글의 지도를 그려주고 싶어서 | 지운다 — 제목과 구조가 이미 지도다 |
| 같은 정보의 반복 (요약에서 말하고 본문에서 또, 끝에서 또) | 강조하고 싶어서 | 가장 잘 보이는 자리 한 곳에만 쓴다 |
| 예고·정리 문장 ("정리하면 다음과 같아요", "결론적으로") | 개조식으로 넘어가는 관성 | 지운다 — 불릿이 곧 정리다 |
| 과잉 구조 (3줄 내용에 섹션 제목·표·구분선) | 격식을 갖추고 싶어서 | 분량이 구조를 정한다. 불릿 몇 개로 끝나면 제목 없이 쓴다 |

> **자가 점검**: 문장을 지워도 독자가 잃는 정보가 없으면 군더더기다. 정보를 잃으면 남긴다 — 줄이는 대상은 문장이지 정보가 아니다 (`references/writing-standards.md §문장`).

## References (필요할 때만 로드)

문장을 실제로 고치거나 놓을 자리가 정해지면 읽는다. 무엇이 들어 있는지만 적는다 — 여기 요약해 두면 reference 를 열지 않게 된다.

| 파일 | 언제 읽을지 |
|---|---|
| `references/writing-standards.md` | 문장을 쓰거나 고칠 때 — 작문 철학, **읽기 수준(용어를 영향으로 환산)**, 용어 처리, 문장·어미·시제, 청중별 우선순위 |
| `references/delivery-context.md` | 놓을 자리가 정해졌을 때 — 성질 축(휘발성·동시성·응답 기대·독자 범위·양식 강제·서식 표현력)별 기준, 판단 순서, 조합 예시, 자리 선택이 틀리는 경우 |
| `references/worked-example.md` | 규칙이 문장에서 어떻게 달라지는지 안 잡힐 때 — 인수인계 메모 한 편을 before/after 로 끝까지 따라간 예시 |

판단 기준은 **도구가 아니라 성질**이다 — 도구 이름은 바뀌어도 성질은 바뀌지 않는다.

## 품질 체크리스트 (기준선 — 어디에 놓든 적용)

내보내기 전에 확인한다. 자리의 성질에 따른 점검은 `references/delivery-context.md §체크리스트` 가 소유한다.

- [ ] 첫 문단(결론)만 읽어도 핵심을 알 수 있는가?
- [ ] 상대가 할 일이 분명한가? (요청이면 무엇을·언제까지, 통보면 할 일 없음)
- [ ] **우리 대화를 못 본 사람이 읽어도 막히지 않는가?** (지시어·별명·암묵적 전제 제거)
- [ ] 왜 / 무엇을 / 어떻게 / 확인 방법 중 빠진 것이 의도적인가?
- [ ] 버린 선택지와 그 이유가 한 줄이라도 남아 있는가?
- [ ] 지워도 정보가 사라지지 않는 문장(메타 서술·중복·예고 문장)이 없는가?
- [ ] 전문용어를 **영향으로** 환산했는가? (설명만 붙이고 끝내지 않았는가)
- [ ] 유행어·커뮤니티 은어를 쉬운 말로 바꿨는가? ("딥다이브" → "깊게 살펴보기")
- [ ] 한 문서 안에서 어미·시제·톤이 일관되는가?
- [ ] 같은 개념을 같은 단어로 일관되게 부르는가?
- [ ] 모든 주장에 검증 가능한 근거가 있는가?
- [ ] 사실과 판단·추정이 구분되는가?
- [ ] 외부 채널로 나가는 글이면 지금 draft 단계인가? (명시적 승인 없이 전송하지 않았는가)
