# 전달 맥락 (Delivery Context)

같은 내용도 **어디에 놓이느냐**에 따라 다르게 써야 한다. 다만 판단 기준을 특정 도구 이름으로 잡으면 도구가 바뀔 때마다 문서가 낡는다 — 도구는 바뀌어도 **성질은 바뀌지 않는다.**

여기서 고정하는 것은 **성질 축**이고, 지금 쓰는 도구가 그 축의 어디에 있는지는 그때그때 판단한다.

기본값(독자 수준·해요체 단문·개조식·한국어)과 맥락 이전 4요소(왜/무엇을/어떻게/확인 방법)는 **어떤 맥락에서도 유지된다** (`SKILL.md`). 이 문서가 바꾸는 것은 포장뿐이다.

---

## 성질 축

각 축이 글의 무엇을 결정하는지가 전부다. 축은 서로 독립이므로 조합해서 읽는다.

### 1. 휘발성 — 흘러가는가, 남는가

| | 흘러감 | 남음 |
|---|---|---|
| 주 독자 | 지금 그 자리에 있는 사람 | **나중에 검색으로 도착하는 사람** |
| 제목 | 불필요 | **제목이 곧 검색어** — 대상·행위·시점을 담는다 |
| 구조 | 제목 계층 없이 평평하게 | 제목 계층·목차·표 |
| 시점 표현 | "오늘", "방금" 가능 | **절대 날짜로** — "현재·최근·곧"은 나중에 의미를 잃는다 |
| 맥락 이전 | 왜 + 무엇을 위주, 나머지는 링크 | **넷 모두** — 특히 버린 선택지 |

> 남는 글에서 *어떻게(버린 선택지 포함)* 를 빼면, 그 글이 남아 있을 이유의 절반이 사라진다.

### 2. 동시성 — 되물을 수 있는가

| | 되물을 수 있음 (동기·대화) | 되물을 수 없음 (비동기·일방) |
|---|---|---|
| 자족성 | 압축해도 된다 — 막히면 물어본다 | **자기완결적이어야 한다** |
| 전제 | 일부 생략 가능 | 전부 복원 |
| 길이 | 짧게 끊어 여러 번 | 한 번에 필요한 만큼 |

되물을 수 없는 맥락일수록 `SKILL.md §맥락 이전`의 자가 점검이 중요하다 — 독자가 막히면 그대로 끝이다.

### 3. 응답 기대 — 상대가 무엇을 해야 하는가

| 성격 | 글에서 달라지는 것 |
|---|---|
| 통보 (할 일 없음) | 결론과 영향만. 질문을 만들지 않는다 |
| 결정 요청 | **선택지 + 각각의 비용 + 기한**을 명시. 질문은 하나로 좁혀 끝에 둔다 |
| 검토 요청 | 무엇을 봐야 하는지 + 읽는 순서 + 확인 방법 체크리스트 |
| 기록 (미래용) | 응답 없음. 대신 재현 가능할 만큼의 맥락 |

- 질문이 여러 개면 번호를 붙여 답하기 쉽게 만든다.
- "확인 부탁드립니다"는 무엇을 언제까지인지 알려주지 않는다 — 요청은 항상 구체적으로.

### 4. 독자 범위 — 누가 읽는지 아는가

| | 지목된 소수 | 불특정 다수·미래 독자 |
|---|---|---|
| 용어 | 공유된 용어는 그대로 | 내부 코드명·은어를 일반 용어로 |
| 전제 | 아는 만큼 생략 | 전부 문장으로 드러냄 |
| 기준 청중 | 그 사람 | **가장 맥락이 적은 사람** |

이 축은 "아는 사람인가"만 다룬다. 아는 사람이라도 **역할에 따라 무엇을 앞에 둘지**는 달라지므로 `writing-standards.md §청중별 우선순위` 를 함께 본다.

### 5. 양식 강제 — 형식이 정해져 있는가

| | 자유 | 고정 양식 |
|---|---|---|
| 구조 | 내용에 맞춰 정한다 | **정해진 섹션을 지킨다** — 이름 변경·생략 금지 |
| 판단 | 무엇을 앞에 둘지 매번 결정 | 양식이 이미 답했다. 채우는 데 집중 |

고정 양식이 있으면 그 양식이 단일 출처다. 여기서 재정의하지 않는다 (예: PR 본문 4단 → `git` 스킬 `references/cli-reference.md`).

### 6. 서식 표현력 — 무엇이 살아남는가

| | 제한적 (플레인 텍스트에 가까움) | 풍부 (리치 문서) |
|---|---|---|
| 표 | 깨진다 — 불릿으로 편다 | 그대로 쓴다 |
| 제목 계층 | 쓰지 않는다 | 쓴다 |
| 코드 | 인라인·짧은 블록만 | 블록 + 링크 |
| 긴 내용 | **다른 곳에 두고 링크** | 본문에 담아도 됨 |

- 어디서든 코드·경로·명령·식별자는 코드 표기로 감싼다. 문장 속에서 눈에 띄어야 오독이 준다.
- 링크는 **대상이 드러나는 문구**로 건다. "여기 참고" 대신 문서 제목을 링크 텍스트에 넣는다.

## 판단 순서

```
1. 남는 글인가?            → 제목·절대 날짜·구조를 갖춘다. 맥락 이전 4요소 전부.
2. 되물을 수 있는가?        → 없으면 자기완결적으로. 전제를 전부 복원한다.
3. 상대가 뭘 해야 하는가?   → 통보/결정/검토/기록에 따라 끝을 정한다.
4. 누가 읽는지 아는가?      → 모르면 가장 맥락이 적은 사람 기준.
5. 양식이 정해져 있는가?    → 있으면 그 양식이 우선. 없으면 결론부터.
6. 서식이 살아남는가?       → 표·계층이 깨지면 불릿으로, 길면 링크로.
```

첫 줄에서 **상대가 할 일**이 드러나는 것은 모든 조합에서 공통이다. 결론을 앞에 두는 것은 자리와 무관한 기준선이라 `SKILL.md` 가 소유한다.

## 조합 예시

| 성질 조합 | 쓰는 법 |
|---|---|
| 흘러감 + 되물을 수 있음 + 결정 요청 | 첫 줄 결론, 불릿 3~5개, 마지막 줄에 질문 하나. 길어지면 문서로 빼고 링크 |
| 남음 + 되물을 수 없음 + 불특정 다수 | 검색되는 제목, 맨 위 3줄 요약, 절대 날짜, 맥락 이전 4요소 전부 |
| 고정 양식 + 검토 요청 | 양식의 섹션을 채우고, 확인 방법은 따라할 수 있는 체크리스트로 |
| 흘러감 + 통보 | 결론 한 줄 + 영향 한 줄. 그 이상은 상대의 시간을 쓴다 |

## 맥락 선택 자체가 틀리는 경우

포장을 아무리 잘해도 **놓는 곳이 틀리면** 전달되지 않는다.

- **남아야 할 내용을 흘러가는 곳에** → 검색되지 않아 같은 질문이 반복된다. 남는 곳에 쓰고 링크를 흘려보낸다.
- **결정이 필요한 것을 남는 곳에만** → 아무도 제때 안 본다. 문서로 쓰고 **결론과 기한은 사람에게 밀어준다**.
- **합의가 안 끝난 것을 고정 양식에** → 검토 자리가 설계 토론으로 번진다. 합의를 먼저 끝내고 결과만 싣는다.
- **되물을 수 없는 자리에 압축한 글** → 되묻는 대신 그냥 오해한 채로 넘어간다.

## 체크리스트 (자리 의존)

기준선 점검(결론 먼저·대화 잔재·4요소·영향 환산·일관성·근거)은 `SKILL.md §품질 체크리스트` 가 소유한다. 여기서는 자리가 바뀌면 답이 바뀌는 것만 묻는다.

- [ ] 이 맥락의 성질(휘발성·동시성·응답 기대·독자 범위·양식·서식)을 짚었는가?
- [ ] 남는 글이라면 제목이 검색어가 되고 시점이 절대 날짜로 박혀 있는가?
- [ ] 되물을 수 없는 글이라면 전제가 전부 복원돼 있는가?
- [ ] 상대가 할 일이 첫 줄에 드러나는가? 요청이면 무엇을·언제까지가, 통보면 할 일 없음이 분명한가?
- [ ] 서식이 그 자리에서 깨지지 않는가? (표·코드·제목 계층)
- [ ] 내용의 성격과 놓는 자리가 맞는가?
