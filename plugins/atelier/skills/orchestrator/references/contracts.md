# Orchestrator Contracts

이 파일은 판단을 담지 않는다. 런타임 사실 · repo 고유 규약 · 값의 단일 출처만 둔다. 기본값 표는 `SKILL.md §기본값 표` 가 갖는다.

## 도구 확보

- 진입 즉시, 다른 어떤 체크보다 먼저 조율 도구의 스키마를 1회 확보한다 — `ToolSearch({query: "select:SendMessage,Monitor,TaskCreate,TaskList,TaskGet,TaskUpdate"})`. 확보한 스키마는 세션 내내 유효하다.
- 대상은 deferred 도구뿐이다. 처음부터 호출 가능한 비-deferred 도구는 결과 목록에 없어도 부재가 아니다.
- 결과 목록에 없는 deferred 도구는 이 런타임에 없는 것이다 — 이름을 추측해 호출하지 않는다. 없는 경로는 폴백으로 대체한다.
- 경량 경로에서도 생략하지 않는다. 조율 경로 전체가 이 확보 하나에 걸려 있다.
- `Monitor` 는 확보는 하되 사용은 긴 빌드·테스트의 stdout 을 줄 단위로 보거나 패턴 즉시 보고가 필요한 dispatch 에만 한정한다(찾을 패턴을 미리 정한다). 일반 위임은 완료 알림이 결과를 실어 오므로 `Monitor` 는 컨텍스트만 늘린다.

## 왕복 조율 가용 판정과 spawn 확인

- 왕복 발신 수단(`SendMessage`)의 스키마를 확보했으면 team 가용, 못 했으면 비가용이다. 진입 시 1회 확정하고 트리거 시점에 다시 판정하지 않는다.
- 지목자는 spawn 스키마의 이름 파라미터이고, 없으면 spawn 반환값의 식별자다 — 이름 파라미터가 없다는 사실을 비가용으로 읽지 않는다.
- 격리 위임은 `Agent` 도구에 `isolation: "worktree"` 를 주어 띄운다 — worktree 와 `worktree-agent-*` 브랜치가 자동 생성된다. 배경 실행은 `run_in_background: true` 다.
- 그 spawn 의 지목자는 `name` 이 있으면 `name`, 없으면 반환된 `agentId` 이고 `SendMessage` 의 수신자로 그대로 쓴다.
- 필수 등급 경로의 첫 spawn 직후, 확보한 지목자로 한 번 발신해 왕복 성립을 확인한다. 이 발신이 첫 조율 지시를 겸하며 확인용 빈 메시지는 보내지 않는다.
- `InputValidationError` 는 스키마 미확보다 — §도구 확보 를 마친 뒤 한 번만 재시도한다. 수신자 없음은 지목자 오류이므로 재발신하지 않고 가용 판정을 다시 한다.

## 브랜치 규약

- `<epic>` 은 진입 절차가 확보한 브랜치의 **전체 이름**이다 — 어떤 접두든 확보한 이름을 그대로 쓰고 접두 형태를 요구하지 않는다. 메인은 그 브랜치를 점유한다.
- 작업 브랜치는 `<epic>-t<task-id>-<slug>` 다. `t<task-id>` 는 Task 의 id 와 같은 값으로 둬 어느 브랜치가 어느 Task 것인지 조회 없이 알 수 있게 한다. `<slug>` 는 영소문자·하이픈 3~5 단어이며, 커밋 메시지 규약(`.claude/rules/git-workflow.md`)과 달리 type prefix 를 붙이지 않는다.
- 격리 인자가 자동 생성하는 브랜치 이름은 agent 식별자라 작업 단위와 연결되지 않는다. **첫 커밋 전에** `git switch -c <epic>-t<task-id>-<slug>` 로 전환하라는 지시를 prompt 에 싣는다 (§prompt 필수 포함 요소 9번). 자동 생성된 `worktree-agent-*` 브랜치는 결과 통합 후 worktree 정리와 함께 삭제한다.
- 계층형 `<epic>/…` 는 `<epic>` ref 가 존재하는 동안 만들 수 없다.
- 후보 수집은 `git branch --list '<epic>-t*'` 하나로 결정적이다. 이 목록과 결과 보고의 worktree 경로·브랜치명을 대조해, 대조되지 않는 것은 고아 브랜치로 표시하고 삭제하지 않는다 — 중단·취소된 작업물이 남아 있을 수 있다.

## 산출 경로 계약

- 무거운 경로 — base epic 브랜치 이름을 prompt 에 싣는다 (§prompt 필수 포함 요소 3번). 격리 규약은 같은 표의 7·9번이 함께 간다.
- 경량 경로 — "결과는 응답 텍스트로 반환하고 파일을 만들지 마라"를 싣는다. 파일이 꼭 필요하면 "산출 경로는 repo 밖 scratchpad 로 한정하라"를 출구로 짝짓는다.
- 계약을 빼면 sub-agent 가 리포트를 tracked 경로에 써서, 경량으로 판정한 런이 사후에 머지 대상을 갖게 된다.

## prompt 필수 포함 요소

sub-agent 는 메인 대화 히스토리를 보지 못하므로 prompt 는 자기완결적이어야 한다. 아래 번호는 안팎에서 "필수 포함 요소 N번"으로 지목되므로 **재배열하지 않는다**.

| # | 요소 | 싣는 형태 |
|---|---|---|
| 1 | 목적 | 무엇을 달성해야 하는가 |
| 2 | 컨텍스트 | 작업 배경 · 관련 파일의 전체 경로 · 이미 알려진 제약 |
| 3 | 브랜치 또는 산출 경로 계약 | 무거운 경로는 base epic 브랜치 이름, 경량 경로는 §산출 경로 계약 |
| 4 | 범위 | 무엇을 하고 무엇을 하지 말 것 |
| 5 | 출력 형식 | 결과를 어떤 형태로 돌려줄지. 어떤 채널로 돌려줄지는 11번이 따로 규정한다 |
| 6 | 검증 기준 | 완료를 무엇으로 확인할지 |
| 7 | worktree 격리 준수 | 격리 위임 시 필수. 매 호출 전 `file_path` 와 cwd 가 자기 worktree 안인지 검증 · 부모 repo 직접 편집 금지 · 이미 만든 변경은 reset·checkout 하지 말고 stash 로 보존한 뒤 보고 |
| 8 | 재위임 금지 | 다른 agent 에게 넘기지 말고 직접 수행하고, 막히면 실패 사유와 함께 종료. teammate 가 편집을 격리 subagent 에 넘기는 한 단계만 예외 |
| 9 | base 확인 + 규약 브랜치 생성 | 격리 위임 시 필수. base 가 위임 시점 epic HEAD 인지 확인해 뒤처졌으면 맞춘 뒤, §브랜치 규약 의 이름으로 브랜치를 만들고 그 위에서만 커밋 |
| 10 | 금지에는 출구를 함께 | 금지 계약마다 "대신 무엇을 하라"를 짝짓는다. 금지만 주면 sub-agent 는 그 상황에서 뭐라도 해야 하므로 위반이 재발한다 |
| 11 | 보고 채널 | 배경 위임 시 필수 — §보고 채널 의 문구를 그대로 싣는다 |
| 12 | hot-spot 편집 금지 + 출구 | 겹치는 hot-spot 이 있으면 필수. 파일을 목록으로 명시해 금지하고, 필요한 항목은 보고하라는 출구를 준다 |
| 13 | 증거 계약 | 조사·탐색·감사 위임 시 필수. 모든 claim 에 실행한 명령 원문과 `file:line` 근거를 붙이고, 못 찾으면 `NOT FOUND — searched with <명령>` 으로 보고 |
| 14 | 탐색 예산 | 조사형 dispatch 에 필수. 값은 §예산과 가드레일 값 에서 읽어 자기완결적으로 싣고, 소진 시 탐색을 멈추고 중간 산출물(발견 사항 · 구체 계획 · 미지 항목)부터 회수하라는 지시를 짝짓는다 |
| 15 | 테스트 인프라 발견 결과 | 테스트 작성·보강을 포함하면 필수. 러너·실행 명령 / 픽스처·헬퍼·팩토리 / 통합 하네스 / 유사 기존 테스트 사례(복수)를 `file:line` 인용으로 확보해 컨텍스트와 검증 기준 양쪽에 싣는다. 부재는 `NOT FOUND — searched with <명령>` 형식으로 받는다 |

## 보고 채널

- sub-agent 가 그냥 출력한 텍스트는 메인에 보이지 않는다. 메인에게 말하는 유일한 채널은 `SendMessage({to: "main", ...})` 다.
- prompt 에 명시할 문구 — "진행 보고·질문·부분 결과는 `SendMessage({to: "main", summary: "<한 줄 요약>", message: "<내용>"})` 로 보내라. 그냥 출력하면 메인에 전달되지 않는다."
- 채널 지시는 spawn prompt 안에 있어야 하고 띄운 뒤에 붙일 수 없다. 최종 완료 알림에는 마지막 출력이 실려 오므로, 조용히 유실되는 것은 완료 이전의 진행·질문·부분 결과다.

## 기록 위치와 형식

- 위치는 `log_dir` (§예산과 가드레일 값). repo 밖이라 커밋 대상이 아니고 메인 워킹 트리 clean 판정도 건드리지 않는다. append-only `log.md` 또는 결정별 `NNNN-<slug>.md` 로 두고 런마다 디렉토리를 분리한다. run-id 는 epic 이름의 `/` 를 `-` 로 치환해 만든다(경량 런은 §예산과 가드레일 값 의 경량 런 식별자).
- 형식(한 결정 = 한 항목): `## <ISO timestamp> · <결정 요약>` 아래 상황 / 참고 / 결정 / 근거 / 대안 / 영향. 상세 근거는 `log_dir` 과 worktree 에 남기고 메인은 경로만 보유한다.
- 참고 소스로 무엇을 봤는지 함께 적는다 — 대화(요구·제약·우선순위), `CLAUDE.md`, `.claude/rules/*`, spec·설계 문서, 코드·git 상태.
- 필수 등급 경로의 기록에는 `실행 형태: teammate | subagent` 와 `판정 근거: 왕복(이름 파라미터) | 왕복(반환 식별자) | 환경` 을 더한다 — 두 필드가 없으면 폴백 여부를 사후에 판별할 수 없어 필수 등급 경로의 기록으로 인정하지 않는다.
- 모든 dispatch 는 기대 완료 시간을 정해 기록에 남긴 뒤 보낸다 — 정하지 않은 채 dispatch 하지 않는다. 한도를 넘겼는데 완료 알림도 중간 보고도 없으면 idle 로 확정한다. 경량 런은 이 절의 기록을 파일 대신 응답 본문(종료 보고)에 남겨도 된다 — §종료 핸드오프 의 경량 예외와 대칭이다.

## 종료 핸드오프

- 위치·시점은 `<log_dir>/HANDOFF.md` 에 종료 시점 1회다. 완료·에스컬레이션·예산 소진·환경 블록 어느 쪽으로 끝나도 같게 남기고, 경량 경로는 파일 대신 종료 보고에 같은 항목을 싣는다.
- 책임 분리: 결정 기록은 "왜 그렇게 했는가"(과정), 핸드오프는 "지금 어디이고 무엇이 막았는가"(상태)다. 한 파일에 섞지 않는다. 작성 주체는 메인이든 sub-agent 든 repo 밖 경로에 쓰므로 격리가 필요 없다.
- 내용: 작업 단위마다 종료 3분류 판정과 그 판정이 요구하는 정보(증거 / 해제 조건 / 미착수 사유), 미해결 항목, 남은 worktree 처리 상태.
- 성립 기준: 다음 세션이 이 기록만 읽고 "어디서 멈췄는지 / 무엇이 막았는지 / 무엇이 갖춰지면 재개되는지"를 알 수 있어야 한다. 대화를 봐야 이해되는 문장이 하나라도 있으면 아직 핸드오프가 아니다.

## 예산과 가드레일 값

**모든 예산·가드레일 수치의 유일한 소유처가 이 표다** — 다른 절과 다른 파일은 이름만 쓴다. 자율 런은 진입 시 이 계약을 한 번 수립해 보고하고, 계약을 벗어나는 순간에만 멈춘다.

| 이름 | 값 | 도달 시 |
|---|---|---|
| `done_when` | 판정 가능한 종료 조건 — 명령(테스트·빌드·lint·git 상태) 또는 산출물 수용(보고 수용 완료, 지정 경로의 산출물 존재) | 판정할 수 없으면 진입하지 않는다 |
| `path` | 경량 \| 무거운 — 진입 시 1회 판정, 역방향 전환 없음 | — |
| `spec_resolved` | 스캔한 spec 경로 목록 + 미결 0. spec 입력이 아니면 `해당 없음` | 생략은 판정이 아니다 |
| `integration_verify` | `command` + `run_at` (`before_merge` \| `after_merge`). 최종 통합 검증 게이트는 `run_at` 과 무관하게 epic 최종 HEAD 에서 같은 `command` 를 한 번 더 돈다. tracked 변경이 있는 런은 필수, 없으면 해당 없음 | — |
| `hard_stops` | 멈추는 조건 목록. spec 입력 런이면 "spec 미결 발견"이 기본 포함 | 예산과 무관하게 즉시 |
| `log_dir` | repo 밖 세션 scratchpad `<scratchpad>/orchestrator/<run-id>/` — run-id 는 epic 이름 또는 경량 런 식별자 | — |
| `max_loops` (+ 가능하면 시간·턴 상한) | 기본 10 · 런마다 계약에 고정 | 멈추고 보고 |
| `max_redispatch_per_task` — 실패와 게이트 reject 후 수정 재위임 | 2~3 | 해당 작업 hard stop |
| `max_council_rounds` | 2 | 협의체 종료 후 보고 |
| `max_advisory_consults` — 단위는 자문 패킷 1건 | 왕복 조율 가용이면 2, 비가용이면 0 | 자문 없이 에스컬레이션 |
| 탐색 예산 | agent 당 30 | 탐색을 멈추고 중간 산출물과 함께 보고 |
| 충돌 카운터 — 파일 단위 | 같은 파일 2회 / 3회 | 2회 재분류·직렬화, 3회 에스컬레이션 |
| no-progress | 연속 3 루프 무진전 (진전은 머지된 브랜치 수 · 통과 테스트 수 · 종료 조건 충족 항목 수로 센다) | 멈추고 보고 |

- 예산은 조정 가능이지 생략 가능이 아니다 — 조정하면 근거와 함께 기록한다.
- 충돌 카운터는 `max_redispatch_per_task` 와 별개 축이고 task 를 갈아치워도 리셋되지 않는다. 자문 예산 0 은 "트리거에 도달해도 쓸 수 있는 것이 없다"는 뜻이라 폴백 여지를 남기지 않는다.

## Task 시스템

등록 여부의 판정은 `SKILL.md §기본값 표` 의 표 7 이 갖는다. 이 절은 등록하기로 한 뒤의 사용법이다.

- **등록**: `TaskCreate({subject, description})` — `description` 에 범위와 검증 기준을 넣는다. 생성 상태는 `pending`.
- **의존성**: `TaskUpdate({taskId, addBlockedBy})` 로 순차 의존을 표현한다. blocked task 는 선행 완료 전에 claim 되지 않는다.
- **소유권**: dispatch 한 상대를 `owner` 로 표시한다 (`TaskUpdate({taskId, owner})`).
- **조회**: `TaskList()` 는 pending·미소유·non-blocked 를 작업 가능으로 보여 주고, `TaskGet({taskId})` 는 전체 요구사항과 `blockedBy` 를 준다.
- **상태 전이**: dispatch 시 `in_progress`, 머지·완료 시 `completed`. 완료는 blocked task 를 자동 해제한다.
- **추적 범위**: 작업 상태(분배·의존성·소유권)만 추적하고 산출 내용은 추적하지 않는다. 전체 transcript 를 메인 컨텍스트로 넘기는 출력 필드는 사용하지 않는다.

## task 도출 계약

확정된 task 목록의 각 항목은 dispatch prompt 의 재료가 되므로 다음 일곱을 반드시 포함한다.

- **id / 목적** — 무엇을 달성하는가
- **범위** — 무엇을 하고 무엇을 하지 않는가
- **예상 변경 파일** — disjoint 판정의 입력. prompt 에 실리는 형태는 §prompt 필수 포함 요소
- **의존성** — 선행 task
- **위험도** — 모델 배정 판정의 입력
- **검증 기준** — 완료를 판정할 결정적 명령 또는 조건
- **필요 게이트 관점** — 이 산출물이 요구하는 검토 관점 목록 (`SKILL.md §기본값 표` 의 표 6). 값 없이 확정하지 않는다 — 비면 관점 누락이 조용히 생긴다

## 설계 승인 마커

- **기록 시점**: 승인 이벤트가 발생했을 때 메인이 기록한다 — 협의체 검증 pass · `grill` 심문 종료 시의 합의 · 사용자의 명시적 설계 승인 중 하나다.
- **기록 위치**: `<log_dir>/design-approval.md` — repo 밖이라 커밋 대상이 아니다.
- **필수 필드** — 아래 셋. 승인 출처가 비면 마커는 성립하지 않는다. 출처 없는 마커는 자기 승인과 구분되지 않는다.

```
## <ISO timestamp> · 설계 승인
- 승인 출처: council pass | grill 합의 | 사용자 승인
- 대상 task: <task id 목록>
- 근거 경로: <협의체 결과 또는 합의 요약이 있는 위치 — grill 합의·사용자 승인이면 커밋된 `plans/YYYY-MM-DD-<slug>.md`>
```

## 대화 스킬의 자율 어댑테이션

협의체에 주입되는 두 자세는 원래 사용자와의 대화를 전제한다. 협의체에는 사용자가 없으므로 다음으로 치환한다.

- **사용자 질문 → 코드베이스 탐색**: 질문이 코드·git 이력·spec 문서로 답해지면 직접 탐색해 해소한다.
- **탐색으로 답할 수 없는 질문 → 명시적 가정**: "가정: X (근거: Y)" 형태로 산출물에 남기고, 심문 검증이 그 가정의 위험도를 판정한다.
- **도메인 의미 결정 → 에스컬레이션 후보**: 틀리면 데이터·의미가 오염되는 결정은 가정으로 덮지 않고 에스컬레이션 항목으로 표시한다.
- **spec 이 미결로 선언한 항목 → 가정 금지**: spec 의 미결은 사용자가 내릴 결정이다. 가정으로 덮거나 대신 확정하면 위반이고, 산출물에 그 항목이 나타나는 순간 회부한다.
- **심문 자세의 "미결 0"(`grill` `SKILL.md §미결·의문 해소 게이트`) → 탐색으로 닫지 못한 항목이 전부 명시적 가정 또는 에스컬레이션 항목으로 기록된 상태**: 되물을 사용자가 없으므로 재질문이 아니라 앞의 두 치환으로 닫는다.
- **설계 생성 자세의 HARD-GATE(승인 전 구현 금지) → 검증 pass 전 dispatch 금지**로 대응된다.

## 자문 계약

- **역할 제한은 계약이지 도구 보장이 아니다.** 자문자는 teammate 이고 teammate 는 도구 권한을 제한할 수단이 없다. 아래 금지는 전부 프롬프트 계약이며 위반은 소집 전후 토폴로지 가드로 사후 탐지한다 — 편집 금지 / 다른 teammate 에게 지시 금지(조율 창구는 메인 하나다) / 능동적 스코프 확장·재위임 금지. 어기면 출력 계약 위반으로 처리하고 권고를 기각한다.
- **입력 패킷은 자기완결적이어야 한다.** 필드는 관점 / 배경(목표 1~2문장) / 막힌 지점 / 질문(모호한 "봐주세요" 금지) / 제약(바꿀 수 없는 조건) / 근거 자료 경로 / 기대 출력 / 금지 계약. 금지 계약은 생략하지 않는다 — 도구로 막을 수 없으므로 이 문구가 유일한 사전 장치다. 긴 근거는 전문 대신 경로로 넘기고, 질문이 여럿이면 우선순위를 매긴다.
- **출력 계약**: 요약 한 문장 / 권고(각각 근거 + severity `critical | important | optional` + 택하지 않은 대안) / 질문 자체에 대한 지적(있을 때만) / 확신도(높음·보통·낮음 + 판단을 흔드는 미확인 사실). 명령형 지시, `pass`·`reject` 판정, 다른 teammate 에 대한 작업 지시는 금지한다 — 자문자는 게이트가 아니다.
- **수명**: 자문 세션 단위로 띄우고 협의체 tie-break 이면 협의체 팀과 함께 끝난다. team 은 session 종료 시 자동 정리된다. 끝난 뒤 메인은 권고 요약과 채택 판단만 컨텍스트에 유지하고 전문은 기록에 둔다.

## 역할별 모델 제약

- **지시로 받는다.** "이 모델은 리뷰어로 쓰지 마라" 같은 제약은 사용자 지시로 받아 런 내내 일관되게 적용하고 근거와 함께 기록한다.
- **역할을 지목한 제약은 그 역할에만 적용된다** — 다른 역할의 기본값이 되지 않는다. 자문 tier 가 조사·구현으로 번지는 것이 흔한 오적용이다. 넓히려면 사용자에게 확인받는다.
- **설정 파일 규약을 두지 않는다** — 파싱·검증하는 코드가 없는 설정 파일은 오타·스키마 위반을 조용히 삼킨다. 세션을 넘겨 유지할 제약은 이미 로드되는 문서(`CLAUDE.md` · `.claude/rules/*`)에 적는다.
- **제약은 tier 선택 범위만 좁힌다.** 어떤 제약도 `SKILL.md §기본값 표` 표 1 사전 기준의 상한을 뒤집지 못하고, 모델명은 그 사전 기준에만 적는다.
- **표준 tier 를 쓸 수 없으면 인접 tier 로 대체한다** — 판정 품질이 게이트인 역할은 인접 상위 우선, 그 외는 인접 하위 우선. 대체는 벗어난 선택이므로 근거와 함께 기록한다.

## Authorship

방침을 지금 처리로 지킬 수 없으면 임의로 진행하지 않고 에스컬레이션한다 (`SKILL.md §정지 조건`).

| 방침 | 명령 | 기록 |
|---|---|---|
| 없음 | committer·author 를 유지하고 trailer(`Co-Authored-By` 등)로 저작자 표시를 보존한다 | 방침 부재와 기본값 적용 사실 |
| 보존 | 단일 커밋은 `git commit --amend --no-edit`, 여러 커밋은 `git rebase --exec 'git commit --amend --no-edit' <base>`. author 는 건드리지 않는다 | 적용 사실과 대상 커밋 범위 |
| 정정 | 위 명령에 `--reset-author` 를 더해 author 도 정정한다 | 적용 사실과 대상 커밋 범위 |

## 사용자 보고 형식

보고 채널·수단은 §보고 채널, 기록 위치는 §기록 위치와 형식 이 소유한다. 이 절은 사용자에게 나가는 보고의 시점과 담을 항목만 정한다.

**시작 시 — 1회**
1. 분해된 작업 목록과 병렬·순차 판정
2. 자율 계약 1회 보고 — 종료 조건 · 예산 · hard stop · 결정 기록 위치
3. 경로 판정 결과와 근거

**진행 중 — 자율은 침묵이 기본**
4. 자율 모드에서 정상 루프는 보고하지 않는다(결정은 기록에 계속 남긴다) — HITL 은 계획 확정 · 게이트 결과 · 머지 전 · 종료 4지점에서 확인을 받는다. 각 절차가 따로 지정한 사용자 결정(epic 선택 · worktree 정리)은 그대로 둔다
5. 에스컬레이션·hard stop 은 모드와 무관하게 즉시 보고한다
6. 정체·실패 보고에 담을 것: 어떤 작업이 어떤 상태인가 · 추정 원인 · 가능한 다음 액션(같은 prompt 재위임 / prompt 수정 후 재위임 / 폐기 / 사용자 직접 처리) · 결정 요청

**종료 시**
7. 종료 사유 — 완료 / 예산 소진 / 에스컬레이션
8. 3분류 판정 요약의 건수 — DONE(검증 증거: 테스트·빌드·lint 결과, 커밋·머지 링크, 열린 PR 이면 push 된 HEAD sha, 편집 없는 런이면 보고 수용 결과) / BLOCKED(에러 + 해제 조건, 해제 조건이 없으면 판정이 아니다) / NOT-STARTED(미착수 사유)
9. 핸드오프 — 무거운 경로는 파일 경로, 경량은 이 보고에 포함
10. 머지 결과 — 성공 / 실패(충돌 파일과 성격) / 보류 후보 목록 · 남은 worktree 경로 · 다음 액션 제안
11. 최종 통합 검증 게이트 — tracked 변경이 있으면 HEAD sha 와 `integration_verify` 결과, 없으면 해당 없음. red 면 완료 선언을 보류하고 원인과 재위임 계획을 함께 적는다
12. 원격 최신화 상태 — push 완료 / 열린 PR 없음 / 위임
13. 의사결정 요약 — 총 결정 수 · 주요 분기 · 전체 기록 경로
14. 판정 근거는 이 문서의 **절 이름**으로 지목한다 (`SKILL.md §불변식` · `SKILL.md §정지 조건` · `SKILL.md §기본값 표`). 시작·진행 중 보고에도 같게 적용한다

실패한 건을 빼거나 수치를 agent 의 말로 세면 사용자가 보는 완료율과 실제 산출물이 어긋나고, 머지 결과를 후보 단위로 적지 않으면 보류된 브랜치가 조용히 사라진다.

## 머지 대상: epic 브랜치

- 머지 target 은 항상 현재 epic 브랜치이고 기본 브랜치가 아니다. 작업 브랜치는 PR 을 만들지 않고 이 브랜치로 수렴한 뒤 삭제되므로 브랜치명이 PR 타이틀이 되지 않는다.
- epic → 기본 브랜치 머지는 이 스킬 범위 밖이다. 외부로 나가는 PR 단위는 `git` skill `SKILL.md §PR 단위 원칙` 이 단일 출처이고, 통합 순서와 가드는 `references/procedures.md §머지 표준 절차` 가 갖는다.
