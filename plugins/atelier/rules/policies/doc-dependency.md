# 문서 의존성 (단방향)

각 문서는 자기 책임만 적고, 의존은 한 방향으로만 가리킨다. 목적은 하나다 — **spec 한 줄을 바꾸면 영향받는 코드만 고치면 되고, 주석·plan·다른 문서를 찾아다니며 고칠 일이 없게 한다.**

판별 질문: **"가리킨 대상이 바뀌면 이 문장도 고쳐야 하는가?"** 그렇다면 그 문장은 의존이다. 아래 방향이 아니면 지우고, 꼭 필요한 사실은 그 문서의 책임 범위 안에서 직접 적는다.

## 층과 방향

```
plan ──→ spec ──→ core
  └──────────────→ core

core: CLAUDE.md · AGENTS.md · rules · skills · agents · commands · output-styles
code(주석 포함): 어떤 문서와도 서로 가리키지 않는다
```

| 층 | 책임 | 가리킬 수 있는 것 |
|---|---|---|
| core | 작업자가 어떻게 일하는가 | 없음. 다른 core 도 가리키지 않는다 — 같은 종류(rule→rule, skill→skill)도 마찬가지다 |
| spec | 제품이 무엇이어야 하는가 (정책) | core |
| plan | 그 시점에 왜 그렇게 구현하기로 했는가 | spec, core |
| code 주석 | 코드에서만 판단할 수 있는 것 (spec·plan 으로 표현할 수 없는 함정·제약) | 없음 |

- core 끼리는 **스킬·에이전트·커맨드를 이름으로 부르는 것**만 허용한다 ("충돌 해결은 `git` 스킬로 위임한다"). 파일 경로, 절 이름(`§…`), rule 이름은 쓰지 않는다. rule 은 경로에 따라 자동으로 로드되므로 부를 필요가 없다.
- 스킬이 자기 `references/` 파일을 가리키는 것은 같은 문서 안의 구성이라 허용한다.
- 문서 **종류**를 말하는 것(spec, plan, `.claude/rules/`, "plan 은 `plans/` 에 남긴다")은 특정 문서를 가리키지 않으므로 의존이 아니다.

## 층별로 쓰지 않는 것

| 문서 | 쓰지 않는 것 | 대신 |
|---|---|---|
| spec | 코드 경로·파일명·식별자·라인, plan 문서 | 정책·계약만 적는다. 코드 위치는 코드에서 찾는다 |
| core | 코드 경로·라인, 특정 spec·plan 문서, 다른 core 의 경로·절 | 필요한 사실을 그 문서 안에 직접 적거나, 스킬·에이전트·커맨드 이름만 부른다 |
| plan | 코드 라인(`file:line`)·코드 조각 | 결정과 근거를 동작·정책 수준으로 적는다 |
| code 주석 | 코드·spec·plan 을 보면 알 수 있는 내용, 문서 포인터 | 코드에서만 판단할 수 있는 것만 남긴다 |

## 바뀌었을 때

| 바뀐 것 | 고칠 곳 |
|---|---|
| spec (정책) | 영향받는 code 만 |
| code (동작 변경) | 정책이 바뀐 것이면 spec. 그 밖에는 없음 |
| code (리팩토링) | 없음. spec·core·plan 을 고쳐야 한다면 그 문서가 코드에 결합된 신호다 |
| core | 그 문서만 |
| 새 결정 | 새 plan 을 쓴다. 기존 plan 은 고치지 않는다 |
