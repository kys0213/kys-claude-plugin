# 에러

실패는 **호출자가 다룰 수 있는 형태로** 알린다 — 반환이든 예외든. 호출자가 판단할 정보는 타입에, 사람이 읽을 정보는 메시지에 담는다.

## 분류

- DO: 호출자가 가를 필요가 있는 실패는 에러를 정의한 곳이 전용 타입·값으로 선언한다. 처리부는 그 타입으로 가른다.
- DON'T: 에러 메시지 문자열을 비교·검색해 종류를 가른다 — 프로덕션·테스트 모두. 문구를 고치면 분류가 조용히 깨진다. 의존성이 판별 수단을 주지 않으면 파싱하지 말고 그쪽 API 개선을 요청한다.
- DON'T: `-1`·빈 문자열·`null` 처럼 정상 범위의 값으로 실패를 알린다. 실패는 별도 경로(에러·없음 표현·예외)로 알린다.

## 감싸기

- DO: 하위 에러를 감쌀 때 원인을 보존해 호출자가 판별할 수 있게 한다. 이렇게 노출한 하위 에러는 계약이므로 문서화하고 테스트한다.
- DO: 덧붙이는 문맥은 하위 에러에 없는 것만 담는다 (어떤 입력, 어떤 단계). 하위 에러가 이미 가진 정보(경로 등)나 실패 사실만 알리는 "failed" 를 반복하지 않는다.
- DO: 시스템 경계(RPC·저장소·외부 API)에서는 내부 에러를 그대로 노출하지 않고 그 경계가 정한 에러로 옮긴다.

## 처리

- DO: 에러는 처리·전달·(진입점에서) 종료 중 하나로 한 번만 다룬다.
- DON'T: 에러를 조용히 버린다. 실패할 수 없음이 보장된 경우만 그 이유를 적고 버린다.
- DON'T: 전달하는 에러를 그 자리에서 로그도 한다. 같은 실패가 여러 번 찍힌다. 기록 여부는 최종 처리자가 정한다.
- DO: 에러를 먼저 처리하고, 정상 흐름은 들여쓰기 없이 이어 간다.

## 프로그램을 멈추는 실패

- DO: 프로그램을 멈추는 실패(panic·처리하지 않는 예외·단언)는 내부 불변식이 깨진 버그에만 쓴다. 사용자 입력·외부 시스템 실패처럼 예상할 수 있는 실패는 에러로 알린다.
- DON'T: 크래시를 피하려고 모든 실패를 잡아 삼키는 복구 코드를 둔다. 깨진 상태가 퍼진다.
- DO: 단언에는 왜 성립해야 하는지와 실패한 값을 문맥으로 남긴다. 조건을 되풀이하지 않는다.

```
DON'T  if err.message.contains("not found") { ... }
DO     match err { NotFound => ..., other => return other }
```
