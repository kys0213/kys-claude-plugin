# 동시성

띄운 작업(스레드·고루틴·태스크)은 **소유자와 끝나는 시점이 코드에 보여야** 한다. 수명이 보이지 않는 작업은 새고, 실패가 아무에게도 보고되지 않는다.

- DO: 동시 작업을 띄우는 코드에서 그 작업이 언제·어떻게 끝나는지 보이게 한다. 띄운 함수는 반환 전에 작업이 끝나기를 기다리거나, 기다리고 멈출 수단(핸들)을 호출자에게 넘긴다.
- DON'T: 끝나는 시점을 모르는 작업을 띄우고 잊는다(fire-and-forget).
- DO: 기본은 동기 API 다. 하위 작업을 반환 전에 끝내고 결과를 직접 돌려준다. 동시성이 필요하면 호출자가 더한다 — 호출자 쪽에서 불필요한 동시성을 걷어내기는 어렵다.
- DO: 동기화 코드는 좁은 범위에 가두고, 로직은 동기 함수로 뽑아 단독으로 테스트한다.
- DO: 취소·시한은 호출자에게서 받아 하위 호출에 그대로 넘긴다. 호출 체인 중간에서 새 취소 루트를 만들지 않고, 구조체 필드에 저장하지 않는다.
- DO: 함께 띄운 작업 묶음은 한 곳에서 결과를 모으고, 하나가 실패하면 나머지를 취소할지 정한다.
- 권장: 공유 가변 상태보다 소유권 이전·메시지 전달을 먼저 고른다. 공유해야 하면 잠금 범위를 짧게 둔다.

판별: 이 작업을 띄운 함수가 반환한 뒤에도 작업이 돌고 있을 수 있는가? 그렇다면 누가 기다리고 누가 멈추는지 코드에서 가리킬 수 있어야 한다.
