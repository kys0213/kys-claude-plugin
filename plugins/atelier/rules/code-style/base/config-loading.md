# 설정 읽기

밖에서 들어오는 설정은 **경계 한 곳에서** 타입 있는 값으로 해석하고, 해석할 수 없으면 그 자리에서 실패시킨다. 잘못된 값이 안쪽까지 흘러가면 실패가 원인과 먼 곳에서 엉뚱한 모습으로 나타난다.

- DO: 환경변수와 설정 파일은 설정 계층 한 곳에서 읽어 타입 있는 설정 값으로 만든다. 나머지 코드는 그 값을 주입받는다.
- DO: 필수 설정이 없으면 시작 시점에 어떤 설정이 없는지 말하며 실패한다.
- DON'T: 코어 로직이나 깊은 하위 함수에서 환경변수를 직접 읽는다. 필요한 설정이 한눈에 안 보이고, 테스트에서 전역 상태를 바꿔야 한다.
- DON'T: 필수 설정에 기본값을 둔다. 누락이 조용히 "그럴듯한 기본 동작"으로 바뀌어 운영에서야 드러난다. 기본값은 정말로 선택적인 설정에만 둔다.

```
DON'T  timeout = env("TIMEOUT") or 30          -- 필수인데 누락이 숨는다
DO     config  = Config.load()                 -- 누락 시 "TIMEOUT 이 없다"로 실패
       service = Service(config.timeout)
```

판별: 이 값이 잘못되었을 때 실패하는 곳이 값이 들어온 곳인가? 아니라면 검사를 설정 계층으로 옮긴다.
