# 추상화와 인자 모양

추상(인터페이스·트레이트·제네릭)은 **필요가 생긴 뒤에** 들인다. 미리 만든 추상은 구현을 하나 더 읽게 하고, 실제 필요가 오면 대개 모양이 다르다.

## 추상

- DO: 인터페이스는 구현이 둘 이상 필요하거나(테스트용 fake 포함) 쓰는 쪽이 구현을 바꿔 끼워야 할 때 만든다. 먼저 구체 구현을 쓴다.
- DON'T: "service"·"repository" 같은 패턴 이름이나 코드 정리만을 이유로 인터페이스를 만든다.
- DO: 인터페이스는 쓰는 쪽이 실제로 호출하는 메서드만으로, 쓰는 쪽 가까이에 정의한다.
- DO: 인자는 필요한 만큼만 추상으로 받고, 반환은 구체 타입으로 한다.
- DON'T: 타입이 하나뿐인 제네릭, 당장 쓰지 않는 일반화(범용 인자 타입, 설정 가능한 훅)를 만든다.

## 인자와 값

- DO: 호출부에서 의미가 안 보이는 `bool` 인자는 이름 있는 열거형으로 바꾼다. 주석으로 때우지 않는다.
- DO: 같은 기반 타입이라 섞이기 쉬운 값(`UserId`/`OrderId`)은 전용 타입으로 감싼다.
- DO: 인자 목록이 길어지면 함수를 나누거나 이름 있는 필드의 옵션 묶음으로 받는다. 위치 인자의 뜻을 호출부 인라인 주석으로 설명하지 않는다.
- DO: 의미 있는 값 묶음은 위치(튜플)보다 이름 있는 필드로 돌려준다.

```
DON'T  render(doc, true, false)
DO     render(doc, Mode::Draft, Toc::Hidden)
```

판별: 이 추상을 지우고 구체 타입으로 바꾸면 지금 무엇이 깨지는가? 깨지는 것이 없으면 아직 필요 없는 추상이다.
