# 라이브러리 API

라이브러리는 **어떤 프로그램에 들어갈지 모른다**. 프로세스 전체에 영향을 주는 결정은 호출자에게 맡기고, 공개 API 는 바꾸기 어려운 계약으로 다룬다.

## 호출자에게 맡기는 것

- DON'T: 프로세스를 끝내거나 처리하지 않는 크래시로 실패를 알린다. 에러를 돌려준다.
- DON'T: stdout·stderr 에 직접 쓰거나 전역 로거 설정을 바꾼다. 기록이 필요하면 호출자가 넘긴 로거를 쓴다.
- DON'T: 전역 상태에 기대는 API(패키지·모듈 수준 변수, 싱글톤, 서비스 로케이터, 전역 콜백 레지스트리)를 노출한다. 상태가 있으면 인스턴스 타입을 주고 호출자가 그 인스턴스를 넘기게 한다.
- DON'T: import·로드 부수효과로 플래그를 등록하거나 환경변수·설정 파일을 읽는다. 설정은 생성 인자로 받는다.
- DON'T: 호출자 모르게 백그라운드 작업을 띄운다. 띄워야 하면 멈추고 기다릴 수단(close·cancel)을 API 로 준다.
- 권장: 편의용 기본 인스턴스가 꼭 필요하면 인스턴스 API 의 얇은 프록시로만 두고, 라이브러리 내부는 그것에 기대지 않는다.

## 공개 API 는 계약이다

- DO: 시그니처·동작·돌려주는 에러 종류를 깨는 변경은 버전으로 알린다.
- DO: 나중에 값이 늘 수 있는 열거형·구조체는 늘어나도 호출자가 깨지지 않게 연다 (언어가 주는 수단을 쓴다).
- DO: 공개 범위는 최소로 둔다. 필요가 확인되기 전에는 비공개로 둔다.
- DO: 호출자가 해야 하는 정리(close·stop)와 돌려줄 수 있는 에러 종류를 문서에 적는다.
- 권장: 의존성은 최소로 둔다. 전이 의존성은 호출자의 빌드 시간·보안 검토 부담이 된다.

판별: 이 동작을 호출자가 끄거나 바꿀 수 있는가? 없다면 그 결정은 라이브러리가 아니라 호출자의 것이다.
