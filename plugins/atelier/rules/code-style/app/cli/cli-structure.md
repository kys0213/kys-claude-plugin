# CLI 구조

CLI 는 **인자 해석 → 코어 호출 → 결과 표현**만 하는 얇은 층이다. 판단과 상태 변환은 코어에 둬야 CLI 없이 테스트하고, 다른 클라이언트가 재사용할 수 있다.

- DO: 명령 핸들러는 인자를 타입 있는 값으로 해석하고, 코어를 호출하고, 결과를 출력 형식으로 바꾸는 일만 한다.
- DON'T: 조건 분기·상태 변환 같은 비즈니스 로직을 명령 핸들러에 둔다. 코어로 옮긴다.
- DO: 코어는 출력하거나 프로세스를 끝내지 않고 값과 에러를 돌려준다. 출력 형식과 종료 코드는 CLI 층이 정한다.
- DO: 같은 입력에는 같은 결과를 낸다. "상황을 보고 알아서" 정하는 동작은 인자로 드러내고, 인자가 없으면 거부하거나 문서화한 기본값을 쓴다.
- DO: CLI 테스트는 인자 → 출력·종료 코드를 보는 블랙박스로 쓰고, 외부 의존성(파일시스템·네트워크·프로세스)은 주입한 fake 로 바꾼다.
- 권장: 서브커맨드마다 모듈을 나눌 필요는 없다. 모듈 경계는 다른 코드와 같은 기준(소비 concern)으로 정한다.

```
handle_check(args):
  paths  = parse(args)            -- 인자 → 타입 있는 값
  report = core.check(paths)      -- 판단은 코어
  print(report.render())          -- 표현
  return report.exit_code()
```
