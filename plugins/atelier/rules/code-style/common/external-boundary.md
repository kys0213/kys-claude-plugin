# 외부 경계

외부 시스템(DB·HTTP API·파일시스템·CLI 프로세스·메시지)과 닿는 코드는 **어댑터 한 겹**에 모으고, 밖에서 온 데이터는 그 경계에서 해석한다. 원시 표현이 코어까지 흘러가면 실패가 원인과 먼 곳에서 엉뚱한 모습으로 나타난다.

## 어댑터

- DO: 외부 시스템과 닿는 코드는 어댑터 단위로 묶고, 코어는 어댑터가 구현하는 추상에만 의존한다.
- DO: 어댑터 전용 타입(외부 응답 형태, 클라이언트 설정)은 어댑터 안에 두고 코어로 새지 않게 한다.
- DON'T: 코어 로직 곳곳에서 외부 클라이언트를 직접 생성·호출한다.

## 경계 데이터 디코드

- DO: 외부 경계 데이터(외부 API 응답, 파일, 메시지)는 전용 타입으로 한 번 디코드한다. 형태 검증(필드·타입)은 디코드가, 의미 검증(범위·관계·업무 규칙)은 그다음 단계가 맡는다.
- DO: 디코드한 결과만 코어로 넘긴다. 코어는 원시 표현(맵, 동적 값, 원문 문자열)을 다루지 않는다.
- DO: 문자열 등 외부 표현을 닫힌 값 집합으로 바꿀 때 모르는 값은 오류로 반환한다.
- DON'T: 원시 표현을 여러 곳에서 조금씩 꺼내 쓰며 그때그때 검사한다.

판별: 이 값이 잘못되었을 때 실패하는 곳이 값이 들어온 곳인가? 아니라면 검사를 경계로 옮긴다.
