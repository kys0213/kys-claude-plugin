# 주석

주석은 **코드만 봐서는 알 수 없는 것**만 담는다. 다른 곳에서 알 수 있는 내용을 복제하면 원본이 바뀔 때 틀린 설명이 된다. 애매하면 쓰지 않는다. 구현·문서·테스트 주석 모두에 적용한다.

- DO: why(자연스러운 대안 대신 이걸 쓴 이유), gotcha(외부 도구·OS 의 비직관적 동작과 회피, 확인한 사실만), 시그니처가 말 못 하는 전제조건·불변식·실패 입력·호출 순서.
- DON'T: spec·정책 복제(코드가 하는 일까지만), 변경 이력·작성자·날짜, 티켓·PR 번호(TODO 도 내용을 적는다), 문서 포인터(지우고 남는 게 없으면 통째로 지운다), 이름·분기를 풀어 쓴 what, 흩어진 로직을 이어 주는 설명(먼저 한곳으로 모은다).
- 문서 주석: 공개 여부만으로 의무화하지 않는다 — 언어 가이드의 "공개 이름마다 문서 주석" 규칙보다 이것이 우선한다. 쓸 때도 위 DO 내용만 담고, 형식은 언어 관용을 따른다.
- 주석 붙은 코드를 고치면 유지 여부를 다시 판단하고, 함정이 사라졌으면 지운다.
- 판별: 다른 문서가 바뀌면 틀려지는가 → 지운다. 지워도 코드로 같은 결론인가 → 지운다. 없으면 함정에 빠지는가 → 남긴다.
- 도구 디렉티브·`TODO:` 마커·사용자 출력 문자열은 서술 대상이 아니다.

```
-- 재시도 1회: 이 클라이언트는 idle 5분 뒤 첫 호출에서 EOF 를 낸다
```
