# 테스트 (Testing)

언어 공통 취향 룰이다. 언어별 룰(Google 스타일 가이드)과 충돌하면 이 룰을 따른다.

이 룰은 테스트 파일 경로로 로드되지만, 경로로 가를 수 없는 테스트(구현 파일 안에 함께 있는 단위 테스트)에도 똑같이 적용한다.

## 의존성은 주입한다

- DO: 테스트 대상은 협력자를 생성자·인자로 주입받게 만들고, 테스트는 인메모리 구현(fake)을 주입한다.
- DON'T: 전역 함수·모듈·싱글턴을 테스트 중에 바꿔치기(전역 mock 치환, monkey patching)한다. 테스트끼리 상태를 공유해 순서·병렬 실행에 따라 결과가 달라지고, 대상 코드가 무엇에 의존하는지 시그니처에 드러나지 않는다.
- DON'T: 주입 지점이 없어서 전역 치환이 필요하다면, 테스트를 우회로 맞추지 말고 대상 코드에 주입 지점을 만든다.

## 구조: AAA, 한 테스트에 한 행동

- DO: 본문을 준비(Arrange) → 실행(Act) → 검증(Assert) 순서로 나눈다. 실행 단계는 한 번이다.
- DO: 한 테스트는 한 행동만 검증한다. 테스트 이름이 그 행동과 기대 결과를 말한다.
- DO: 검증은 최종 결과(반환값, 관찰 가능한 상태)를 기준으로 한다. 내부 호출 순서·횟수는 그것이 곧 계약일 때만 검증한다.
- DON'T: 한 테스트에서 실행과 검증을 여러 번 반복해 여러 행동을 확인한다. 첫 실패가 뒤 검증을 가려, 무엇이 깨졌는지 한 번에 보이지 않는다.
- DON'T: 단계 마커 주석에 서술을 붙인다. 마커는 단계 이름만 쓰고 맥락은 테스트 이름으로 옮긴다.

```
rejects_expired_token:
  -- arrange
  clock  = FixedClock(at = "2026-01-02")
  auth   = Auth(clock, tokens = FakeTokens([expired_on("2026-01-01")]))
  -- act
  result = auth.verify("t1")
  -- assert
  expect result == error(Expired)
```

## fake 는 테스트 본문 밖에 둔다

- DO: fake·테스트 더블·픽스처 생성기는 테스트 본문 밖(테스트 지원 모듈, 같은 파일의 보조 항목)에 정의하고 여러 테스트가 재사용한다.
- DO: fake 는 실제 구현과 같은 계약(인터페이스)을 만족한다. 계약을 어기는 fake 는 거짓 통과를 만든다.
- DON'T: 테스트마다 본문 안에서 협력자 구현을 즉석으로 정의한다. 본문이 준비 코드에 묻혀 검증하려는 행동이 보이지 않는다.

## 외부 인프라 의존은 단일 축으로 가른다

- DO: 테스트를 나누는 축은 하나, **외부 인프라(네트워크, 실제 DB, 외부 서비스, 특정 머신 환경)에 의존하는가**다.
  - 의존하지 않는 테스트: 기본 실행에 포함하고 CI 에서 항상 돈다.
  - 의존하는 테스트: 언어의 표준 표시 수단 하나로 표시해 기본 실행에서 빼고, 명시적으로 요청할 때만 돈다. 표시에는 무엇이 필요한지 적는다.
- DON'T: "느림", "통합", "중요" 같은 여러 축을 섞어 표시한다. 어떤 테스트가 CI 에서 도는지 축마다 따로 따져야 한다.
- DON'T: 외부 인프라가 없으면 테스트 안에서 조용히 통과(return)시킨다. 돌지 않은 테스트가 통과로 보고된다.
