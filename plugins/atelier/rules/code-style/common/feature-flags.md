# 피쳐 플래그 남용 금지

피쳐 플래그는 **배포와 출시를 떼어 놓는 임시 장치**다. 플래그 하나마다 테스트할 동작 조합이 두 배가 되고, 아무도 켜지 않는 쪽 경로는 실행되지 않은 채 낡는다.

- DO: 런타임에 켜고 끌 이유(점진 출시, 운영 중 즉시 차단, 실험)가 있을 때만 만든다. 만들 때 제거 조건과 담당을 함께 적는다.
- DO: 플래그는 진입점·조립 계층 한 곳에서 읽어 구현 선택으로 바꾼다. 안쪽 코드는 주입된 구현만 알고 플래그를 모른다.
- DO: 출시가 끝나면 플래그와 꺼진 쪽 코드를 같은 변경에서 지운다.
- DON'T: 같은 플래그를 여러 함수·모듈에서 검사한다. 분기가 흩어지면 지울 때 빠뜨리고, 켠 쪽과 끈 쪽이 반쯤 섞인 상태가 생긴다.
- DON'T: "혹시 되돌릴지 몰라서" 플래그 뒤에 숨긴다. 되돌리기는 버전 관리로 한다.
- DON'T: 영구적인 동작 차이(고객별 옵션, 환경별 값)를 플래그로 둔다. 그건 타입 있는 설정이나 별도 구현이다.
- DON'T: 플래그끼리 중첩하거나 다른 플래그 값에 기대게 한다. 테스트 전용 분기도 플래그로 만들지 않고 의존성 주입으로 바꾼다.

```
DON'T  quote():    if flags.new_pricing { ... } else { ... }
       invoice():  if flags.new_pricing { ... } else { ... }
DO     pricer   = flags.new_pricing ? NewPricer() : LegacyPricer()   -- 조립 시 한 번
       checkout = Checkout(pricer)
```

판별: 이 플래그를 언제, 무엇을 보고 지우는지 말할 수 있는가? 말할 수 없으면 플래그가 아니라 설정이거나 필요 없는 분기다.
