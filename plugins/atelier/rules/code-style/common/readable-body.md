# 읽히는 본문 (Readable Body)

언어 공통 취향 룰이다. 언어별 룰(Google 스타일 가이드)과 충돌하면 이 룰을 따른다.

진입 함수(공개 API, 핸들러, 커맨드 실행부, 유스케이스)의 본문은 **무엇을 어떤 순서로 하는가**가 한눈에 보이는 의사코드 수준으로 쓴다. 읽는 사람은 본문만 보고 흐름을 파악하고, 필요한 단계만 골라 들어간다.

## DO

- 본문은 단계 이름의 나열로 읽히게 한다. 각 단계는 의도를 말하는 이름의 하위 함수나 협력자 호출이다.
- 검증, 계산, 외부 호출, 영속화는 각각 하위 함수나 협력자에 위임한다. 진입 함수는 이들을 조율만 한다.
- 한 함수 안의 문장은 같은 추상 수준을 유지한다. 단계 호출 사이에 저수준 세부(인덱스 계산, 바이트 조작, 문자열 조립)가 끼어 있으면 그 세부를 함수로 뺀다.

```
handle(request):
  input   = validate(request)
  order   = price(input)
  saved   = orders.save(order)
  notify(saved)
  return saved
```

## DON'T

- 검증·계산·외부 호출·영속화를 한 본문에 인라인으로 섞는다. 흐름을 파악하려면 전체를 읽어야 하고, 한 관심사를 고칠 때 다른 관심사를 건드리게 된다.
- 단계를 구분하려고 본문 안에 구역 주석(`-- 1. 검증`, `-- 2. 저장`)을 단다. 구역이 필요하다는 것 자체가 함수로 뺄 신호다.
- 이름 없는 단계를 만들려고 함수를 쪼갠다. 추출한 함수에 의도를 말하는 이름을 붙일 수 없으면 추출하지 않는다.

## 추출 신호

다음 중 하나가 보이면 단계를 하위 함수로 뺀다.

- 지역 변수가 계속 늘어난다 — 여러 단계의 중간 상태가 한 스코프에 섞였다는 뜻이다.
- 한 함수에 관심사가 섞여 있다 — 검증과 영속화, 계산과 외부 호출이 같은 본문에 있다.
- 함수가 하는 일을 한 줄로 요약할 수 없다 — "A 하고 B 하고 C 도 한다"가 된다.

## 범위

- 하위 함수 자체는 이 룰의 대상이 아니다. 한 가지 일을 하는 짧은 하위 함수는 세부를 직접 담아도 된다.
- 위임만 하는 한 줄 함수는 만들지 않는다. 단계 추출은 이름이 의도를 말할 때만 한다.
