# 응집 (Cohesion)

언어 공통 취향 룰이다. 언어별 룰(Google 스타일 가이드)과 충돌하면 이 룰을 따른다.

코드는 **그 코드를 소비하는 concern** 기준으로 묶는다. 만든 사람이나 기술 종류(모든 타입, 모든 상수) 기준으로 묶으면, 한 기능을 고칠 때 여러 곳을 열어야 하고 무엇이 어디서 쓰이는지 보이지 않는다.

## 배치는 사용처 수로 정한다

| 사용처 | 배치 |
|---|---|
| 1곳 | 소유하는 타입의 비공개 항목, 또는 그 모듈 안 지역 항목 |
| 모듈 2곳 이상 | 공유 모듈로 승격한다 |

- DO: 한 타입만 쓰는 보조 함수·상수는 그 타입 옆에 비공개로 둔다.
- DO: 두 번째 소비 모듈이 생긴 시점에 공유 모듈로 옮긴다. 옮길 때 이름과 공개 범위를 다시 정한다.
- DON'T: "나중에 공유할지도 모른다"는 이유로 미리 공유 모듈로 추출한다. 실제 두 번째 사용처가 생길 때까지 보류한다 — 사용처 없이 추출하면 경계를 추측으로 긋게 되고, 추측한 경계는 나중에 다시 옮겨야 한다.
- 공유 모듈은 범용 이름(util 등)이어도 된다. 판단 기준은 이름이 아니라 "실제로 2곳 이상이 쓰는가"다.

## 외부 시스템 어댑터

- DO: 외부 시스템(DB·HTTP API·파일시스템·CLI 프로세스)과 닿는 코드는 어댑터 단위로 묶고, 코어는 어댑터가 구현하는 추상에만 의존한다.
- DO: 어댑터 전용 타입(외부 응답 형태, 클라이언트 설정)은 어댑터 안에 두고 코어로 새지 않게 한다.
- DON'T: 코어 로직 곳곳에서 외부 클라이언트를 직접 생성·호출한다.

## 위임만 하는 층은 걷어낸다

- DO: 한 줄로 다른 함수에 그대로 위임하는 함수·래퍼는 호출부에 inline 한다.
- DON'T: 인자를 그대로 넘기기만 하는 중간 함수를 "계층을 맞추려고" 남긴다. 읽는 사람이 한 단계 더 따라가야 할 뿐 얻는 것이 없다.
- 예외: 위임이 외부 경계(공개 API, 추상의 구현)를 이루는 경우는 남긴다.

```
DON'T  load_user(id) := repo.find_user(id)   -- 사용처 1곳, 그대로 위임
       caller → load_user(id)
DO     caller → repo.find_user(id)
```

## 판별 질문

- 이 항목을 지우면 영향받는 곳이 한 모듈뿐인가? → 그 모듈 안에 둔다.
- 공유 모듈에 사용처가 1곳만 남았는가? → 그 사용처 쪽으로 되돌린다.
