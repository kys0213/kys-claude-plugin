# 실패 정책

> 실패는 스레드에 드러내요. 기본값이나 다른 동작으로 덮지 않아요.

## 역할

- 어떤 실패가 어디에 어떻게 보이는지, 실패 뒤 상태가 어떻게 남는지를 정해요.

## 정책

| 실패 | 사용자에게 | 상태 |
|------|------------|------|
| Claude 비정상 종료 | 오류 요약을 스레드에 게시 | 잠금 해제 |
| Claude 결과를 해석할 수 없음 | 오류 요약을 스레드에 게시 | 잠금 해제 |
| `discord` CLI 호출 실패 (`ok:false`, 형식 불일치) | 가능하면 스레드에 오류 게시 | 잠금 해제 |
| 스레드를 만든 뒤 Claude 실행 전에 실패 | 그 스레드에 오류 게시. 스레드는 지우지 않아요 | 잠금 해제 |
| 같은 스레드에서 실행 중 | "이전 작업이 끝난 뒤 다시 멘션해 주세요" | 실행하지 않음 |
| 질문 응답 없음 (마감 지남) | "Discord에서 시간 안에 답이 없었어요" 를 답으로 돌려주고 Claude 가 판단 | 질문은 마감 처리 |
| `ask create` 실패 | 스레드에 알리고, 위와 같은 미응답 답을 돌려줘요 | 실행은 계속 |
| auto 모드의 도구 거부 | 거부된 도구와 사유를 알림 | 실행은 계속 |
| 기록된 작업 디렉토리가 없어짐 | 오류를 스레드에 게시. 기본값으로 대체하지 않아요 | 실행하지 않음, 잠금 해제 |

- 왜 드러내나: 조용히 실패하면 사용자는 Discord 에서 왜 답이 없는지 알 길이 없어요.
- 왜 덮지 않나: 디렉토리 없음 → 다른 디렉토리로 대체 같은 보정은 엉뚱한 곳에서 Claude 가 일하게 만들어요.

## 오류 요약 형식

- **실패 유형 + 원인 마지막 20줄 이내를 코드블록**으로 올려요.
- 스레드가 없어서 알릴 수 없으면 플러그인 상태 디렉토리의 로그에 기록해요.
- 플러그인은 항상 자체 로그를 남겨요. 훅 stdout 은 버려지고 stderr 는 백그라운드 데몬에서 보이지 않아서, 로그가 유일한 사후 단서예요 ([discord-cli-contract](discord-cli-contract.md)).
- 오류 요약 본문에도 봇 멘션 무력화를 적용해요 ([conversation-session](conversation-session.md) 의 "게시 규칙").

## 에러 처리

- 오류를 게시하는 일 자체가 실패해도 잠금은 풀어요.
- 결과 게시는 `send --split` 으로 한 번에 올려요. 나눠 보내는 일은 CLI 가 해요.

## 제약 조건

- 모든 종료 경로(성공·실패)에서 잠금이 풀려야 해요.
