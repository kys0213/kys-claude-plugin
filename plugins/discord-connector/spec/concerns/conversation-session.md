# 대화 이어가기·작업 디렉토리·동시성

> 스레드 하나를 Claude 대화 하나로 묶고, 그 대화가 쓰는 디렉토리를 고정하고, 같은 스레드에서 실행이 겹치지 않게 하는 정책이에요.

## 역할

- 스레드와 Claude 대화의 대응, 대화가 쓰는 작업 디렉토리, 프롬프트에 넣는 내용, 실행 겹침 처리를 정해요.
- 작업 디렉토리 선택 자체는 CLI 몫이에요 ([discord-cli-contract](discord-cli-contract.md)). 여기서는 받은 디렉토리를 어떻게 다루는지만 정해요.

## 프롬프트 정책

- 프롬프트에는 **스레드 링크**(서버 ID·스레드 ID 로 만든 `discord.com` 링크)와 **트리거 메시지**, 위 안내만 넣어요.
- 최종 답이 스레드에 자동 게시된다는 사실을 함께 알려요.
  - 왜: 모르면 Claude 가 직접 게시하려 하거나 엉뚱한 안내를 덧붙여요(실환경 E2E 관측).
- 이력을 읽거나 잘라 넣지 않아요. 얼마나 읽을지는 Claude 가 판단해요.
- 프롬프트에서 `discord` CLI 사용법을 안내하지 않아요. 읽는 방법은 사용자 환경의 `discord` 스킬이 알려 줘요.
  - 왜: 이력 범위·분량 판단을 플러그인이 하면 정책이 늘고, Claude 가 필요한 만큼 읽는 편이 맥락에 맞아요.

## 대화 이어가기 정책

| 상황 | 동작 |
|------|------|
| 스레드에서 첫 실행 | 새 대화로 시작해요. 끝나면 대화 식별자(`session_id`)와 실행에 쓴 디렉토리를 스레드별로 기록해요 |
| 같은 스레드의 이후 실행 | 기록된 대화를 `--resume` 으로 이어요. 기록된 디렉토리에서 실행해요 |
| 최상위 메시지가 트리거 | 스레드를 먼저 만들고 그 스레드에서 첫 실행으로 시작해요 |
| 스레드 안 트리거 | 스레드를 새로 만들지 않아요 |

- 스레드 안은 봇 멘션이 있을 때만 이어가요.
- 한 번의 실행은 한 턴이 끝나면 종료해요. 다음 실행은 다음 멘션이 시작해요.
- 모델은 sonnet 고정이에요. 설정 항목이 아니에요 ([claude-code-dependencies](claude-code-dependencies.md)).

## 작업 디렉토리 정책

- 디렉토리는 CLI 가 정해서 훅 입력의 `cwd`(절대경로)로 넘겨요. 플러그인은 설정 파일을 갖지 않아요.
- 첫 실행의 디렉토리를 스레드와 함께 기록하고, 이어가기는 **훅이 준 값이 아니라 기록된 디렉토리**를 계속 써요.
  - 왜: Claude 세션이 실행 디렉토리 기준으로 저장돼서, 디렉토리가 바뀌면 `--resume` 이 깨질 수 있어요.
- 기록된 디렉토리가 없어졌으면 기본값으로 대체하지 않고 스레드에 오류를 알려요 ([failure-policy](failure-policy.md)).

## 동시성 정책

- **같은 스레드의 실행은 동시에 하나**예요. 다른 스레드끼리는 동시에 돌 수 있어요.
- 이미 실행 중인 스레드에서 새 트리거가 오면 실행하지 않고 "이전 작업이 끝난 뒤 다시 멘션해 주세요" 를 스레드에 올려요.
  - 왜: 같은 대화를 두 프로세스가 이어가면 상태가 꼬여요. 큐는 요구되지 않았어요.
- 실행이 끝나거나 실패하면 같은 스레드의 잠금은 반드시 풀려요.

## 실행 독립성

- Discord 에서 시작한 실행은 CLI 데몬이 재시작돼도 끊기지 않고 끝까지 진행해 결과를 게시해요.
  - 왜: 데몬 업데이트·재시작이 진행 중인 작업을 죽이면 안 돼요.

## 게시 규칙 (무한 루프 방지)

플러그인이 Discord 에 쓰는 모든 메시지(결과·안내·오류·거부 알림·질문)는 아래를 지켜요.

- **스레드 안에만** 써요. 채널 최상위에는 쓰지 않아요.
- `send --reply-to`(답장)를 쓰지 않아요.
  - 왜: CLI `send` 는 답장 알림을 끄지 않아요. 그래서 Discord 가 답장 대상 작성자를 멘션으로 넣고, 그 작성자가 봇 자신이면 다시 트리거돼요.
- 본문의 봇 멘션 `<@봇ID>`·`<@!봇ID>` 를 일반 텍스트로 바꿔 무력화해요. 봇 ID 는 훅 입력의 `bot_user_id` 예요.
  - 왜: `trigger_bots`(봇이 쓴 메시지도 훅을 부르게 허용하는 CLI 설정, [discord-cli-contract](discord-cli-contract.md#필터는-cli-가-맡아요))에 봇 자신이 있으면, 봇 멘션이 든 메시지가 다시 트리거돼요.

## 에러 처리

- 실패 시 잠금 해제와 오류 게시는 [failure-policy](failure-policy.md) 를 따라요.
- 실패한 실행도 스레드는 지우지 않아요.

## 제약 조건

- 대화 식별자와 디렉토리는 스레드별로 하나씩만 기록해요.
